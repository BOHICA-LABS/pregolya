## Process-Level

### L-001 [process-gap, codified]: §17-C Status-Code Census Was Inert — Positive-Coverage Assertion Required

**Discovered:** Pass 25 (burst 101)
**Symptom:** The §17-C census in bc-authoring-plan.md was structured as an absence-check only — it would report PASS if no disallowed codes were present, but never grep-verified that required PASS-row codes (201, 204, 502, 503, 504) actually appeared in the target status table. F-P25-07 revealed that 201/204/502/503/504 rows were absent from the status table yet §17-C had been reporting PASS for multiple prior passes.
**Root cause:** Census was written as "verify no bad codes" without a complementary "verify all expected good codes exist" assertion.
**Codified fix:** §17-C now requires a positive-coverage assertion: for each code in the MUST-APPEAR list, grep the status table and fail the census if any expected row is absent. Implemented in bc-authoring-plan.md §17-C.
**Applicable to:** Any census gate that validates presence of a required set (not just absence of a forbidden set). Both halves are required for completeness.

### L-002 [process-gap, codified]: BC Absolute "Must Not Diverge" Invariants Must Carry Precedence Carve-Outs

**Discovered:** Pass 25 (burst 101)
**Symptom:** BC-2.14.002 contained an absolute invariant "per-endpoint status codes MUST NOT diverge from the categorical table" with no exception mechanism. This made the spec self-contradictory: the categorical table is correct as a default-floor, but legitimate per-endpoint contracts (e.g., CRON endpoints returning 201) necessarily override the floor.
**Root cause:** Invariant was authored as a blanket prohibition rather than as a default-with-explicit-override policy.
**Codified fix:** BC-2.14.002 now states that the categorical table is the default floor; per-endpoint status rules documented in the endpoint's own BC take precedence and are not divergence — they are intentional extensions. The invariant now reads as "per-endpoint rules must be explicitly documented and must not contradict the categorical table without a stated rationale."
**Applicable to:** Any BC invariant using absolute prohibition language ("must not", "never", "always") — these should be audited for whether a legitimate override pathway exists and documented if so.

### L-003 [process-gap, codified]: Manual Positive-Coverage Census Not Re-Run After Wildcard Narrowing

**Discovered:** Pass 27 (burst 103)
**Symptom:** The §17-C positive-coverage census (codified in L-001, burst 101) was not re-run after pass-26 narrowed the 422-row wildcard to 8 enumerated VAL E-GRAPH codes. The census row for E-GRAPH-002 remained green (from a pre-narrowing run) despite E-GRAPH-002 now being in a three-way contradiction: it appeared in taxonomy as POLICY (returning 422), the status table showed a wildcard-narrowed 422 row covering VAL codes only, and BC-2.14.002 PC3 had no entry for it. F-P27-01 (HIGH) found the gap.
**Root cause:** The census is a manual step. No gate enforced re-running it when a prerequisite artifact (the status table) changed. The census result was treated as a cached pass.
**Codified fix:** Gate #21 CENSUS RE-RUN TRIGGER added to bc-authoring-plan.md: whenever any status-table wildcard is narrowed or any E-code taxonomy category is changed, §17-C census MUST be re-run before the fix burst is closed. This gate is checked as a sibling-check in the next adversarial pass.
**Deferred improvement (NOT yet codified):** Machine-enforce the census grep via CI/hook — orchestrator to open a follow-up story or deferral entry at cycle close per S-7.02.
**Applicable to:** Any multi-step authoring plan where a downstream census depends on upstream artifact state. Cache invalidation must be explicit: record WHICH artifacts the census depends on and trigger re-run when any of them change.

### L-004 [process-gap, codified]: Wire-Visible Taxonomy With No Standing Gate Drifts Undetected

**Discovered:** Pass 29 (burst 105)
**Symptom:** The streaming-event surface (SSE chunk type, domain events, envelope keys) had drifted across 5 artifacts — BC-2.12.007, interface-definitions.md, ADR-006, events.md, module-decomposition.md — using inconsistent names (node_delta vs node_stream; past-tense variant names vs imperative canon; astream_events wire-compat claim vs D13 native-wire). None of this was caught through 28 adversarial passes because no standing gate covered streaming-event name coherence. F-P29-03/04/05 (3 HIGH findings) all stem from this single root cause.
**Root cause:** Every wire-visible taxonomy (errors, events, objects) needs its own coherence census from the moment it first appears in specs. The streaming-event surface was introduced in early Phase 1 BCs and ADRs but was never given a corresponding coherence gate — unlike error taxonomy (gated via §17-C census) or wire objects (gated via §18-C sub-field census).
**Codified fix:** Gate #23 STREAMING-EVENT-NAME COHERENCE added to bc-authoring-plan.md: every wire-visible event name (SSE chunk type, domain event, envelope key) must appear consistently in events.md, the StreamEvent enum in ADR-006 (11 imperative variants), and any BC that references it; census must be re-run after any streaming-surface change.
**Applicable to:** Any new wire-visible taxonomy introduced during spec authoring — the moment a named set of events, codes, or objects appears across more than one artifact, a coherence census gate must be added for it. Do not wait for an adversarial pass to discover the gap.

### L-005 [process-gap, codified]: Census Regexes Must Enumerate All Punctuation Forms; Censuses Must Detect Collisions, Not Just Drift

**Discovered:** Pass 34 (burst 110)
**Symptom:** Gate #16 (E-code/variant coherence census) policed space-delimited pairings only (e.g., `E-RETRY-003 CircuitBreakerOpen`). It did not grep colon-delimited forms (e.g., `E-RETRY-003: CircuitBreakerOpen`) nor cross-check each pairing against the error-taxonomy authoritative binding to detect collisions. As a result, E-RETRY-003 carried two contradictory meanings across the BC boundary — error-taxonomy defined it as CircuitBreakerOpen (POLICY/Later) while BC-2.16.001 EC-003 used the same code for InvalidRetryLimit — and this collision survived all 33 prior adversarial passes undetected.
**Root cause:** (1) Census regex matched only one punctuation form; spec authors use both forms interchangeably. (2) Census checked for name-drift (does the code name match across files?) but not for collision (does one code name map to two different concepts?). Both checks are required.
**Codified fix:** Gate #16 widened to two grep forms (space-delimited AND colon-delimited E-code↔variant pairings) + cross-check every pairing against the error-taxonomy authoritative binding (collision detection, not just name drift). Codified in bc-authoring-plan.md gate #16 (D18-P34-C). Full-corpus sweep of 44 pairings confirmed ZERO additional collisions post-fix.
**Applicable to:** Every census gate that polices named identifiers across multiple artifacts. The census must: (a) enumerate ALL punctuation/formatting forms the pattern can appear in; (b) perform both drift-check (name matches across files) AND collision-check (one identifier maps to one concept only). These are two orthogonal failure modes requiring two orthogonal assertions.

### L-006 [process-gap, codified]: Canon-Retirement Fixes Must Sweep Structurally-Privileged Lines

**Discovered:** Pass 36 (burst 112); second instance of class first seen at Pass 27 (F-P27-02)
**Symptom:** Canon-retirement/amendment fixes that update body prose can leave the retired claim alive in structurally-privileged lines — H1/H2/H3 headings (especially "## Decision:" blocks in ADRs), Summary cells/blocks, and index/registry rows. These lines are read with higher cognitive weight by skimming reviewers and by specs that anchor on them. F-P36-01 found ADR-006's "## Decision:" heading still claiming "JSON-serialized to LangGraph format" even though pass-29's fix had correctly updated the body prose. The heading survived 7 adversarial passes because reviewers read the corrected body and accepted it. Two class instances total: F-P27-02 (ARCH-INDEX summary cell) and F-P36-01 (ADR-006 Decision heading).
**Root cause:** Body-prose-only fixes leave first-class misleading artifacts that skimming reviewers absorb. No prior gate required greping privileged-line locations separately from body prose after a canon-retirement fix.
**Codified fix:** Gate #26 STRUCTURALLY-PRIVILEGED-LINE CANON CHECK added to bc-authoring-plan.md v1.1: every canon-retirement or canon-amendment fix must grep H1/H2/H3 headings (especially "## Decision:"), Summary cells/blocks, and index/registry rows across the affected document AND all documents that cite it, verifying the retired claim is absent from those locations. Also: total_standing_gates frontmatter field added to bc-authoring-plan.md. Codified as D18-P36-D.
**Applicable to:** Any fix that retires or amends a claim embedded in multiple artifact tiers (body prose + privileged structural lines). Both tiers require independent sweep coverage. The privileged-line sweep is an additional check on top of the body-prose fix — not a replacement.

### L-007 [process-gap, codified]: Sibling-Coherence Gates Must Enumerate Derived Documents, Not Just Registries

**Discovered:** Pass 37 (burst 113)
**Symptom:** Gate #25 Part B named only 2 documents for criticality-sibling coherence (arch registry + PO registry). It omitted module-decomposition.md and verification-coverage-matrix.md, both of which derive their criticality column from the authoritative module-criticality.md. F-P37-01 found that the pass-31/32 criticality reconciliation updated the two registries but left 4 incorrect cells + 1 heading in module-decomposition.md unchanged. F-P37-02 found verification-coverage-matrix.md's tier summary still showed 6/7/5/2=20 (stale) instead of 9/12/10/2=33. Both findings survived 5+ adversarial passes because the sibling-set gate did not name the derived documents as required participants.
**Root cause:** Sibling-coherence gates were written to cover authoritative source documents only. Derived documents — those that echo or summarize information from an authority — were assumed to be self-correcting or were forgotten entirely when the gate was initially authored.
**Codified fix:** Gate #25 Part B WIDENED to a 4-doc sibling set: arch registry [authoritative], PO registry, module-decomposition.md, verification-coverage-matrix.md. Any module tier change must propagate to all four in the same burst; census greps each module's tier across all four; gate #26 cross-referenced for privileged tier headings. Codified as D18-P37-C.
**Applicable to:** Any coherence gate that polices a named attribute (criticality tier, pagination convention, error code binding, etc.) that appears in BOTH an authoritative source AND one or more derived/summary documents. The gate must name every document that echoes the attribute — not just the authority. When a new derived document is created, the corresponding coherence gate must be updated before the burst closes.

### L-008 [process-gap, codified]: Consumable Derived Tables Must Be Verified Carriers in Anchor Censuses

**Discovered:** Pass 40 (burst 116)
**Symptom:** bc-authoring-plan.md batch tables (the per-batch BC/CAP/DI/NE authoring work-order tables) were not included in gate #13's four-way anchor census. Sub-burst agents consume these batch tables directly when authoring BCs, so any drift in the tables propagates into the work products even when all authoritative carriers (BC body, BC-INDEX, PRD, RTM) are correct. F-P40-01 found BC-2.08.007's DI cell said "DI-014" only, omitting DI-009. The mandatory full 86-row sweep triggered by the fix burst found 7 MORE drifted cells: BC-2.08.001..005 carried spurious CAP-011, BC-2.10.004 carried spurious CAP-006, BC-2.05.006 carried spurious ASM-008. All 8 cells survived 39 adversarial passes because the batch-table column was not a census carrier.
**Root cause:** Gate #13 anchor matrix was written to cover authoritative source documents (BC body, BC-INDEX, PRD, RTM). It did not include the authoring-plan batch tables, which function as a derived work-order surface that agents consume at authoring time. Any consumable derived table must be a verified carrier or it becomes a silent vector for drift.
**Codified fix:** Gate #13 WIDENED to five-way: body ↔ BC-INDEX ↔ PRD §2/§7/§9 ↔ authoritative registry ↔ bc-authoring-plan batch-table CAP/DI columns. Batch-table corrections must occur in the same burst as BC changes. Full sweep: 8 cells fixed, zero remain. Codified as D18-P40-A. NEW CONVENTION: batch-table/INDEX Cap column = primary capability (frontmatter only); secondary traced capabilities live in body traces_to only (D18-P40-B).
**Applicable to:** Any derived table or work-order artifact that agents consume directly at authoring time. The moment a table is established as a work-order input for downstream agents, it must be added as a verified carrier to the relevant anchor census. "Read-only" or "summary" status does not exempt a table from being a census carrier if agents read it to produce output.

### L-009 [process-gap, codified]: Free-Text Prose Carriers Need Their Own Census

**Discovered:** Pass 42 (burst 118)
**Symptom:** BC Architecture Anchor bullets (free-text prose, e.g., "Architecture Anchor: ferrochain-core/src/graph/builder.rs") were not covered by any standing census. BC-2.08.011 and BC-2.08.012 both cited ferrochain-core/src/graph/builder.rs as the anchor for the StateGraph builder API, when the correct owning crate per ADR-007/module-decomposition/BC-2.02.001 is ferrochain-graph/src/graph/state.rs. F-P42-01 (HIGH) found this wrong-crate anchor in both BCs simultaneously (blast-radius-2). The error survived 41 adversarial passes because gate #13 censuses the anchor column in batch tables and BC-INDEX but not the free-text "Architecture Anchor:" bullets inside BC bodies.
**Root cause:** Column-based anchor censuses (gate #13) are blind to free-text prose fields. Architecture Anchor bullets are written in prose, not tabular cells, so no regex over a column header could find them. A distinct carrier class — free-text anchor prose — existed with zero census coverage.
**Codified fix:** Gate #27 CRATE-RESOLUTION CENSUS added to bc-authoring-plan v1.5: every ferrochain-<crate>/src/... path appearing in any BC Architecture Anchor bullet must (a) name an ADR-007 roster crate and (b) assign the module to its owning crate per module-decomposition. Trigger: every anchor-editing burst + every adversary rotation. Full census at gate #27 mint: 187 paths, 86 BCs, 16 distinct crates, all roster-valid; only the 2 known wrong-crate anchors found, zero remain post-fix. Codified as D18-P42-A.
**Applicable to:** Any free-text prose field that encodes a structural claim (file paths, crate names, module ownership). Column-based censuses cover tabular carriers. Free-text prose carriers require their own dedicated census with a grep pattern targeting the prose syntax. When a new free-text structural field is introduced in spec authoring, the corresponding census gate must be added at the same time — not discovered by the next adversarial pass.

### L-010 [process-gap, codified]: Version Metadata Is Itself a Carrier Needing Census

**Discovered:** Pass 43 (burst 119)
**Symptom:** 17 BCs across ss-04, ss-11, and ss-13 carried `version: 1.1` with `modified: []` (empty) and no changelog entry — a self-contradictory state that misled any consumer about their revision history. The inconsistency survived 42 adversarial passes undetected because no census policed the coherence of the version/changelog pair. Per-file git-history adjudication revealed two sub-classes: 13 BCs with genuine content changes (error-code recategorizations, CheckpointSaver rename, invariant rewrites — kept v1.1, changelog added); 4 BCs with metadata-only touches (bc_id/status field changes in bursts 77-98 — reverted to v1.0, modified: [] eliminated).
**Root cause:** Version-metadata coherence (version > 1.0 implies changelog entry) was never expressed as a census requirement. The `modified: []` vestigial field was a silent false-negative signal: non-empty version with empty-modified is self-contradictory but was never flagged by any carrier census or gate.
**Codified fix:** Gate #28 VERSION-CHANGELOG INTEGRITY added to bc-authoring-plan v1.6: any BC with version > 1.0 MUST carry at least one changelog entry per version bump (frontmatter `changelog:` or `## Changelog` table); `modified: []` is vestigial and must not be used as a substitute for a proper changelog entry. Census greps version ≠ 1.0 vs changelog presence; also applies adjudication policy (D18-P43-A): metadata-only git history = unmodified → revert to v1.0. BC version distribution at gate #28 mint: 55×1.0, 23×1.1, 6×1.2, 2×1.3 = 86 total; zero version>1.0 without changelog post-fix. Codified as D18-P43-A/B.
**Applicable to:** Any versioned artifact (BCs, specs, supplements) where a version bump is expected to be accompanied by a change record. The version field and the changelog field are co-dependent: bumping one without updating the other creates an internally inconsistent artifact. A census gate must validate both sides of the invariant — not just that versions are well-formed, but that every version > baseline is accompanied by evidence of what changed.

### L-011 [process-gap, codified]: Census a Table's Every Semantic Column — Cross-BC Prose Characterizations Are Seam Carriers

**Discovered:** Pass 45 (burst 121)
**Symptom (F-P45-01):** verification-coverage-matrix.md listed the retry module under ferrochain-graph while 6 authoritative sources (module-criticality.md, ARCH-INDEX, BC-INDEX, PRD §2, module-decomposition.md, bc-authoring-plan batch-table) consistently mapped retry to ferrochain-core. Gate #25 Part B ran a tier-census only — it greps each module's criticality tier across the 4-doc sibling set but does not compare the crate-ownership column. The tier values were identical (both MEDIUM), so the drift was invisible to a tier-only census. The 33-row full crate-ownership diff (gate #25 Part C) found the retry row as the sole mismatch.
**Symptom (F-P45-02):** BC-2.05.006 line 178 characterized budget escalation as "a High-tier interrupt" — directly contradicting BC-2.10.004's complete contract (BudgetEscalation payload, BudgetResume::Extend|Halt, orchestrator resume permitted, no risk-tier gate). This cross-BC prose characterization of another BC's contract was a seam carrier: Related-BCs / referenced-BC prose lines encode behavioral claims about a second BC, but no census policed that those claims match the referenced BC's actual preconditions.
**Root cause:** (1) Multi-column tables are censused only on the column that motivated the census design — other columns drift silently. (2) BC body prose that characterizes or summarizes another BC's behavior (Related-BCs sections, cross-reference lines) is a seam carrier needing verification against the referenced BC's PCs; it was treated as informational annotation.
**Codified fix (F-P45-01):** Gate #25 Part C minted — per-row crate-ownership diff: grep each module row across the 4-doc sibling set for its crate column value; any tier-identical crate-divergent row = HIGH finding. (D18-P45-C) **Codified fix (F-P45-02):** D18-P45-B seam canon: budget escalation reuses the BASE interrupt mechanism (BC-2.05.001) with BudgetEscalation payload + BudgetResume::Extend|Halt; NOT risk-tiered, NOT High-tier-gated; orchestrator resume permitted. Cross-BC prose characterizations of another BC's contract are seam carriers requiring verification against the referenced BC's actual PCs.
**Applicable to:** Any census gate that operates on a multi-column table: enumerate and census EVERY semantic column, not just the one that motivated the gate. When a BC body characterizes another BC's behavior (Related-BCs prose, cross-reference lines), treat that characterization as a seam claim needing PCs verification — not just a label.

### L-012 [process-gap, codified]: Supplement Tables Restating BC-Governed Behavior Are High-Risk Derived Carriers

**Discovered:** Pass 47 (burst 123)
**Symptom:** interface-definitions.md Flag-Interaction table row (both sandbox backends off) mandated a SILENT PROCESS-BACKEND FALLBACK — directly inverting BC-2.13.001 PC3/PC4/EC-002's explicit prohibition (SandboxBackend::default() NEVER returns process; both-enforcing-off ⇒ Err(E-SBXD-003); unsafe_process_no_isolation() is the only caller-side escape hatch). This CRITICAL security inversion lived in the supplement for 46 adversarial passes undetected because supplement tables were treated as interface documentation artifacts rather than as BC-derived artifacts that must be diffed against the BCs they cite.
**Root cause:** No standing census policed supplement table rows against the governing BCs they cite. Supplement tables were reviewed for internal consistency and structure but not for behavioral contradiction against the PCs/ECs of the BCs they reference. A derived carrier that RESTATES another artifact's behavioral contract is the highest-risk class: it looks authoritative to a reader but has no automatic cross-check against the authority.
**Codified fix:** Gate #29 SUPPLEMENT-VS-BC SEAM CENSUS added to bc-authoring-plan v1.8: every BC-citing supplement row must be diffed against the cited BC's PCs/ECs; any contradiction = HIGH or CRITICAL finding; trigger: supplement edits + every adversary rotation. First census run: 6 SS-13 rows PASS, 0 additional mismatches. Codified as D18-P47-A.
**Applicable to:** Any derived artifact (supplement table, interface table, feature matrix, configuration reference) that restates behavior governed by a BC. The moment a supplement row claims "behavior X when condition Y", it must be a census carrier for the BC that governs that behavior. "Interface documentation" status does not exempt a table from being a census carrier if it encodes behavioral claims.

### L-016 [process-gap, codified]: Type-Resolution Censuses Must Assert Name Equality With the Cited Authority

**Discovered:** Pass 60 (burst 136)
**Symptom:** Gate #31 (type-resolution census, minted in pass 58) checked that every public type in a trait signature had a resolvable definition site — but it did not verify that the resolved definition matched the identifier cited in the BC. F-P60-01 found that `BudgetDecision` in interface-definitions and ADR-009 resolved to an extant definition while ALL FOUR ss-10 BCs declared the canonical return type as `PolicyDecision`. The type "resolved" — it pointed at something — but it pointed at the wrong thing relative to the authority.
**Root cause:** The census was written as a definition-existence check: "does a definition site exist for this type?" It was not written as a name-equality check: "does the identifier in the derived document EQUAL the identifier declared as authoritative in the BC?" These are two orthogonal assertions. Existence without equality passes the census while masking a critical naming split.
**Codified fix:** Gate #31 WIDENED — step 4 now requires name equality: the identifier in interface-definitions (and every other derived doc) must EQUAL the identifier cited in the governing BC. A census pass requires (a) definition exists AND (b) name matches the BC-authoritative identifier. First application: BudgetDecision RETIRED, PolicyDecision propagated to interface-definitions v2.15 and ADR-009 v1.1. bc-authoring-plan v2.3. Codified as D18-P60-B.
**Applicable to:** Any census gate that validates type resolution across derived documents. Existence checks are a necessary but insufficient subset of a correct resolution census. Always pair the existence assertion ("a definition for this type exists in the corpus") with the equality assertion ("the identifier in this doc matches the identifier declared authoritative in the cited BC"). Divergence between the two is a high-severity spec inconsistency even when both identifiers have valid definitions.

### L-015 [process-gap, codified]: Fixes Introducing New Spec Surface Must Apply Their Own Standard to Everything They Ship

**Discovered:** Pass 58 (burst 134)
**Symptom:** Pass-57 fixed one undefined type (GuardrailError) while simultaneously shipping a new trait block that referenced two more undefined types (IngressContent, GuardrailSeverity). The fix applied the "undefined type" standard to the ONE type it removed, but not to the NEW types it introduced. F-P58-02 (HIGH) and F-P58-01 (MED) found both new undefined types in the very next pass — a partial-fix regression on pass-57's own rationale.
**Root cause:** Fix bursts focus on the identified defect and the immediate fix surface. They do not automatically audit every NEW identifier introduced in the same fix for the same class of defect. A fix that removes a gap while creating two more is a net negative — the convergence counter correctly treats it as regression material even though the original finding was resolved.
**Codified fix:** Gate #31 TYPE-RESOLUTION CENSUS minted (bc-authoring-plan v2.2): every public type named in a trait signature, enum definition, or BC type annotation must have a resolvable definition site within the spec corpus. Census runs after every burst that touches trait blocks or type-referencing prose. First run: 22 types — 20 resolved, 1 external (serde_json::Value, documented), 2 implementer-scope (ChatConfig/CheckpointConfig, documented). Codified as D18-P58 series.
**Applicable to:** Any fix burst that introduces new named identifiers (types, traits, enum variants, error codes). Before closing the burst, enumerate every new identifier introduced and verify each one has a resolvable definition site. "The fix works" is insufficient — all NEW surface introduced by the fix must also pass the same completeness bar that motivated the fix.

### L-014 [process-gap, codified]: A Code-Registry Census Is Blind to the Absence of Codes — Sweep the Constructors

**Discovered:** Pass 56 (burst 132)
**Symptom:** OBS-P56-2 found that sweeping the error-code registry (taxonomy file, BC-INDEX code column) cannot detect error constructions in BC bodies that lack a catalogued code entirely. 23 Err(FerrochainError{...}) construction sites in BC bodies were carrying bare-category strings, TBD placeholders, or cross-BC ellipsis references instead of catalogued codes. These sites were invisible to all prior census passes because every census started from the registry (what codes exist?) rather than from the call sites (where are codes used?).
**Root cause:** Code-registry censuses operate on the inventory of known codes. They have no mechanism to detect a constructor site that skips the code field entirely. The registry remains PASS while the spec silently carries uncoded error paths.
**Codified fix:** Gate #30 CODELESS-ERROR CENSUS added: sweep every Err(FerrochainError{...}) pattern in BC bodies; each site must carry a catalogued code. Ellipsis forms exempt ONLY if a specific code is declared in the SAME BC (cross-BC references insufficient). Category labels must use exact taxonomy tokens (e.g. VAL not Validation). First sweep: 23 sites examined, 15 fixed, 4 new codes minted (E-CORE-006, E-CORE-007, E-PROV-008, E-CHKPT-007), 3 already-coded, 5 exempt. Orchestrator enforced full-class drain in the same burst (second PO dispatch). Codified as D18-P56-B.
**Applicable to:** Any spec using constructor-style error expressions. The moment this pattern is used, a sweep of all constructor sites — not just the code registry — must be part of every census rotation. Partial drains invite re-flagging: commit to full-class drain in a single burst.

### L-013 [process-gap, codified]: Negative-Space Probing Finds Gaps Invisible to Coherence Censuses; Adversary Findings Require Orchestrator Verification Before Routing

**Discovered:** Pass 49 (burst 125)
**Symptom (a):** The graph super-step ceiling (LangGraph recursion_limit / GraphRecursionLimitExceeded) was absent from every spec artifact — error taxonomy, all BCs, all supplements. No coherence census could detect it because no artifact mentioned it; there was nothing to cross-check. BC-2.08.002's "configurable step limit" field was dangling. The gap survived 48 adversarial passes because all prior probes were seam-coherence probes (does artifact A match artifact B) rather than negative-space probes (what behavior is present in the upstream reference but absent from specs entirely). F-P49-02 found it via direct negative-space inspection of the upstream PregelLoop execution model.
**Symptom (b):** F-P49-01 claimed BC-2.08.011/012 + BC-2.07.002 lacked changelog entries — a census gate #28 violation. Orchestrator verification found the finding was false: those BCs carry `## Changelog` body tables (confirmed at lines 138/145/196), but the adversary grepped only frontmatter `changelog:` keys (Form A). Gate #28 text was ambiguous about two-form support.
**Root cause (a):** Seam-coherence censuses can only verify what is present. They are structurally blind to absent specifications. The upstream feature inventory (reference corpus behavioral intent files) is the only source of truth for "what should exist but doesn't." Scheduled negative-space probes against the upstream feature inventory are the only mechanism to close this class of gap.
**Root cause (b):** Gate #28's census description did not explicitly enumerate both changelog forms (frontmatter `changelog:` key AND `## Changelog` body table). Adversary agents implementing the gate independently may check only one form.
**Codified fix (a):** Schedule negative-space probes — "consult the upstream feature inventory and identify any mechanism not yet specified" — as a mandatory adversary probe axis alongside seam-coherence checks. The negative-space axis is productive across the entire convergence loop, not just early passes.
**Codified fix (b):** Gate #28 now explicitly states two-form union census (Form A: frontmatter `changelog:` ∪ Form B: `## Changelog` body table); bc-authoring-plan v1.9 (D18-P49-C). FP-rejection precedent recorded: orchestrator verification is mandatory before routing adversary findings to fix burst.
**Applicable to:** (a) Any spec convergence loop: schedule at least one negative-space probe per rotation against the upstream feature/behavior inventory. (b) Any census gate that accepts multiple equivalent forms: enumerate ALL valid forms explicitly in the gate definition. Findings that rely on a single-form grep against a multi-form standard are false positives until verified.

### L-018 [process-gap, codified]: Traceability Must Be Censused in Both Directions — Forward and Reverse

**Discovered:** Pass 66 (burst 142)
**Symptom:** OBS-P66-1 found that no standing gate covered the reverse direction of error-code traceability: given a catalogued code in the taxonomy, does the code's declared anchor BC actually contain that code, the correct variant name, and a raise condition? Gate #30 (minted pass 56) censuses forward (every Err() constructor in a BC carries a catalogued code). No gate censused reverse (every catalogued code has a behavioral home in the BC it claims as anchor). This blind spot allowed 3 codes — E-SERVER-005, E-CHKPT-003, E-MCP-003 — to survive 65 adversarial passes while orphaned, mis-anchored, or contradicting the very BC they cited as authority. The defect class was first identified at pass 28 (OBS-P28-2) but was addressed only at the instance level; the axis was never gated, and 3 new instances accumulated over the next 37 passes.
**Root cause:** A single directional traceability census is incomplete. Forward census (construction sites carry codes) and reverse census (code registry entries are honored in anchor BCs) are two orthogonal checks. Closing one does not close the other. Fixing individual instances without gating the axis leaves the class open.
**Codified fix:** Gate #33 TAXONOMY ANCHOR REVERSE-VERIFICATION minted (bc-authoring-plan v2.7): every live error code's declared anchor BC must contain that code identifier, its variant name, and a raise condition; trigger: any taxonomy edit or census rotation; post-fix census 78/78 anchored. Codified as D18-P66-C.
**Applicable to:** Any spec where a registry (error taxonomy, event catalog, type catalog) names an "anchor" document for each entry. The census must run in both directions: forward (every use site has a registry entry) and reverse (every registry entry is honored in its claimed anchor). Fixing instances is insufficient — the axis must be gated so the class cannot silently re-accumulate.

### L-017 [process-gap, codified]: An ADR That Decides Placement Is Not Self-Executing — Carriers Must Be Reconciled in the Deciding Burst

**Symptom:** ADR-009 decided that core::budget holds the BudgetPolicy trait and associated types (Option-3: trait-in-core). **Codified fix:** Gate #32 ADR-PROPAGATION CENSUS minted (bc-authoring-plan v2.4): every ADR with a placement decision must be reconciled against module-decomposition, all BC Architecture Anchor paths in the relevant subsystems, and all interface headers in the same burst that finalizes the ADR. Gate #31 near-name extension (D18-P61-B): any UNRESOLVED type in a trait signature census must be cross-checked against near-name corpus concepts before the census closes. Both codified as D18-P61-A/B.
**Applicable to:** Any ADR that assigns a type, trait, or module to a specific crate or file path. The ADR record is necessary but not sufficient — every downstream carrier must be updated in the same burst. "Will be propagated later" is a process gap waiting to be found. The near-name discipline applies universally: any new type name introduced into a spec with prior related type names must pass a corpus near-name search before minting.

### L-019 [process-gap, codified]: Enforcement Tooling and Cross-Doc Notes Are Placement-Canon Carriers

**Discovered:** Pass 70 (burst 146)
**Symptom (F-P70-01):** Gate #27's ownership rule + quick-check enforcement command still forbade ferrochain-core/src/budget — contradicting the pass-61 ADR-009 canon (core/budget is canonical per D18-P61-C). The pass-61 fix updated BC anchors, module-decomposition, and interface headers but not the enforcement command in bc-authoring-plan. Two false HIGH hits against canonical anchors resulted. The gate policed the OLD placement rule because the enforcement tooling was never updated to reflect the new canon.
**Symptom (F-P70-02):** A 401-row note in error-taxonomy stated "reserved" (accurate at P25 when E-PROV-004 was a placeholder) but went stale at P26 when E-PROV-004 was canonized as categorical-fallback. The note referenced another document's row content; when that row was edited, the cross-doc note silently fell behind.
**Root cause:** (1) Gate enforcement commands (census grep patterns, ownership rules, quick-checks) are themselves placement-canon carriers — they encode the canon in executable form. A relocation adjudication that doesn't update the gates policing placement leaves those gates enforcing the OLD canon, producing false positives against the new canon. (2) Cross-doc notes that describe another document's row content go stale silently when the source row is edited; no gate required re-verifying such notes after row edits.
**Codified fix:** Gate #32 scope extended to include enforcement commands (D18-P70-A): every ADR-propagation burst must update not only module-decomposition + BC anchors + interface headers, but also any gate enforcement command or census tooling that polices the affected placement. Gate #29 scope extended to cross-doc row-notes (D18-P70-B): taxonomy notes referencing interface-definitions row content must be verified on every row edit; 401 note = categorical-fallback phrasing (aligned v1.10).
**Applicable to:** Any spec artifact that encodes a claim about another document's content (cross-doc notes, gate enforcement commands, quick-checks, census grep patterns). These are derived carriers with zero automatic coherence enforcement. When source content changes, all derived carrier expressions of that content must be updated in the same burst.

### L-020 [process-gap, codified]: Large Spec Expansions Land With Predictable Fresh-Content Defect Density

**Discovered:** Pass 72 (burst 150)
**Symptom:** The first adversary pass after the D20 spec expansion (burst 149: 9 new BCs, ADR-012, CAP-020/021, all carriers) found 8 integration defects — 2 HIGH and 6 MED. Defect classes: SkillStore interface signature drift (name-keyed vs namespace/key-keyed), stale ADR universe arithmetic (skills row self-contradiction), missing attribution authority (mcp::server placement never canonized in an ADR), and registry lag (PO criticality registry not updated with new modules). None were in the new content in isolation — all were integration failures where new content failed to cohere with existing specs.
**Root cause:** Spec expansions introduce many new artifacts simultaneously. The authoring agents update the primary artifacts (BCs, ADR, CAP) but the inter-artifact coherence checks require an adversary pass with fresh context and all-document access. The convergence counter correctly resets on expansion, but the FIRST post-expansion pass is always a discovery pass, not a convergence pass — fresh-content defect density is structurally higher than steady-state passes.
**Codified fix:** Budget one full scrutiny+fix cycle per expansion before expecting CLEAN passes. Gate #32 carrier list must include EVERY criticality/inventory view (not just the authoritative registry, but also the derived PO view — D18-P72 series established that both the arch-view module-criticality and PO-view criticality registry are required gate #32 carriers for any burst adding new modules).
**Applicable to:** Any spec expansion that adds 5+ new artifacts simultaneously. The authoring burst and the first post-expansion adversary pass form a coupled pair — do not expect CLEAN until the pair completes. When gate #32 is updated for a new ADR, explicitly enumerate every criticality view (arch + PO) in the carrier list.

### L-023 [process-gap, codified]: Adversary Axis Targets Must Be Existence-Validated Before Clearing or Carrying Forward

**Discovered:** Pass 123 (burst 208)
**Symptom (OBS-P123-a):** The carry-forward axes from passes 121 and 122 included "ss-09 §Tool/§McpServer" and "ss-15 ↔ §MemoryStore." When pass-122 cleared "ss-09 §Tool/§McpServer — Reviewed — no ContentBlock vocabulary drift; seam types correct," no sections named §Tool or §McpServer exist in interface-definitions.md. Similarly, §MemoryStore was absent until fix burst 126. The "PASS" verdicts were vacuous — nothing was reviewed. Related defect (F-P123-01): the CORRIGENDUM-1 Explanation for rows 2/8 re-embedded the exact field-name conflation (ContentBlock::ToolUse with Tool-entity fields) it was correcting, undetected because corrigendum prose was written by the implementer without fresh-context adversarial review and then treated as authoritative.
**Root cause:** (1) Axis labels are free-form text that names spec sections. When sections don't exist or are renamed, stored labels silently become phantom targets. No gate required section-existence verification before an axis was cleared. (2) Corrigendum prose (and other audit-trail content) is written during fix bursts by implementation agents who have accumulated context — exactly the conditions under which the original defect arose. Without a fresh-context adversary pass reviewing corrigendum text, a corrigendum can re-embed the defect it was correcting.
**Codified fix:** (1) Before clearing or carrying forward any named-section axis, the adversary MUST grep-verify the named section exists in the target document. If absent, mark PHANTOM-SECTION (not PASS) and route to appropriate specialist to add the section or retire the axis. (2) Treat corrigendum prose as a first-class adversary target on the NEXT pass — the corrigendum Explanation should be read as carefully as spec content. (3) Axis label retirement protocol: when a section is renamed or a phantom axis is identified, explicitly mark the axis as RETIRED in the next carry-forward list with the phantom-section justification (not silently dropped).
**Applicable to:** All adversary passes that inherit named-section axis labels from prior passes. All fix bursts that produce corrigendum prose in burst-log.md or other audit-trail artifacts.

### L-025 [process-gap, codified]: BC-INDEX DI-Anchor Column and bc-authoring-plan DI Table Must Be Swept on Every di_anchors Frontmatter Change

**Discovered:** Pass P1D-137 / burst-237 (F-P137-01/02/03)
**Symptom:** Pass P1D-137 returned 3 MED findings — all derived-table propagation gaps sharing one root cause. When BC-2.13.002's `di_anchors:` frontmatter was updated to `[DI-006, DI-015]` in burst-235 (F-P135-05), three derived tables were NOT swept: (1) BC-INDEX.md DI Anchors column for BC-2.13.002 remained `DI-006`; (2) bc-authoring-plan.md DI Invariant Enforcement Coverage table had no DI-015 row; (3) bc-authoring-plan.md DI-009 row still listed BC-2.23.005 (re-anchored to DI-015 in burst-234 F-P134-06). **Root cause:** The D18-P89-A end-of-burst sweep protocol covers input-hash currency but does NOT explicitly enumerate the derived table artifacts that must be reconciled when a BC's `di_anchors:` frontmatter changes. BC-INDEX.md DI-anchor column and bc-authoring-plan DI Invariant Enforcement Coverage table are both derived from BC `di_anchors:` frontmatter fields, but were not in any sweep checklist. 4. **prd.md §7 RTM DI column** — the BC's RTM row must match frontmatter DI anchors
This is an extension of the post-burst sweep discipline (D18-P89-A / gate #28). It does not require a new gate number — it is a scope extension of the existing end-of-burst sweep obligation.
**Applicable to:** Any burst that edits `di_anchors:` frontmatter in any BC file (including co-enforcement designations, re-anchoring from one DI to another, or minting a new DI). The sweep applies to the BC file's own index/plan carriers plus all upstream DI Invariant Enforcement tables.

### L-026 [process-gap, codified]: Handoff-Flag Closure Scan Required at Every Fix-Burst Close

**Discovered:** Pass P1D-138 / burst-238 (F-P138-01/02/03 + recurring pattern from F-P133-09, OBS-P136-A)
**Symptom:** Pass P1D-138 returned 3 findings (1H + 2M) — all stale completed-handoff flags written by delegation signals ("ARCHITECT FLAG", "PO must", "architect to assign", "amendment required") into source-of-truth artifacts where the delegated work had already been completed in earlier bursts. F-P138-01: error-taxonomy E-TOOLS-009 stale "ARCHITECT FLAG" (work minted in burst-233); F-P138-02: api-surface annotation "pending architect…"; F-P138-03: BC-2.23.006 "architect to append" (work done in burst-229). Corpus-wide proactive sweep found 12 additional instances of the same class beyond the 3 reported.
**Root cause:** The factory writes cross-agent delegation flags directly into source-of-truth spec artifacts as inline annotations. No guardrail exists to clear satisfied flags after the delegated work completes. The flags accumulate as stale residue across bursts, appearing as defects to fresh-context adversary passes. This class has recurred across passes P1D-133 (F-P133-09), P1D-136 (OBS-P136-A), and now P1D-138 (F-P138-01/02/03).
**Codified fix:** At every fix-burst close AND the Cycle-Closing Checklist, run a handoff-flag closure scan: grep the spec corpus for handoff-flag phrases ("ARCHITECT FLAG", "PO must", "architect to assign", "amendment required", "candidate — architect", "pending X authoring/registration") whose cited target artifact/version is already satisfied at HEAD; convert satisfied flags to past-tense facts, leave genuinely-open future-phase placeholders. Immutable changelog rows exempt.
**Applicable to:** All fix-bursts that close findings; all agents that write delegation/handoff annotations into spec artifacts. The scan is a last-act obligation before the burst commit, analogous to the D18-P89-A hash-currency sweep.
