# VP-012: OnWatermark Arithmetic — Trigger Fires Iff tokens_remaining / ceiling <= (1.0 - fraction); No Overflow; Disabled Never Fires

## Property Statement

For all valid `(tokens_remaining: u64, ceiling: u64, fraction: f64)` tuples where
`0 <= tokens_remaining ≤ ceiling` and `fraction ∈ (0.0, 1.0]`, the pure function
`check_watermark_trigger` returns `true` if and only if
`(tokens_remaining as f64) / (ceiling as f64) <= (1.0 - fraction)`. `Disabled` never
produces a trigger. No integer overflow or `f64::NAN` arises on any valid input.

The non-strict `<=` (not strict `<`) is load-bearing: `fraction = 1.0` must fire when
`tokens_remaining == 0` (EC-002 in BC-2.10.005). With strict `<`, the condition
`0.0 / ceiling < 0.0` is always false — EC-002 would never fire. With `<=`, the condition
`0.0 <= 0.0` is true. ✓

**Formal invariant (DI-014):**
```
∀ tokens_remaining: u64, ceiling: u64, fraction: f64:
  0 <= tokens_remaining ≤ ceiling  ∧  0.0 < fraction ≤ 1.0  →
    check_watermark_trigger(tokens_remaining, ceiling, fraction)
      == ((tokens_remaining as f64) / (ceiling as f64) <= (1.0 - fraction))

∀ fraction: f64, 0.0 < fraction ≤ 1.0:
  (1.0 - fraction) ∈ [0.0, 1.0)          // no NaN; subtraction does not underflow below 0

∀ tokens_remaining: u64, ceiling: u64:
  0 <= tokens_remaining ≤ ceiling  →
    (tokens_remaining as f64) / (ceiling as f64) ∈ [0.0, 1.0]  // no NaN; ceiling > 0
```

The `Disabled` variant is never passed to `check_watermark_trigger` (the caller inspects
the variant before calling); the function is only invoked for the `OnWatermark` case. The
proof bounds the integer inputs to a tractable sub-range of u64 to keep CBMC state space
finite while preserving arithmetic generality.

## Source Contract

- **BC:** BC-2.10.005 — CompactionTrigger Configuration — Disabled/OnWatermark/OnMessageCount/OnTokenCount; BudgetConfig Extension; Watermark Arithmetic (VP-012 Kani Seed)
- **ADR anchor:** ADR-019 Decision 3, step 1 — Watermark check: the pure arithmetic comparison `tokens_remaining / ceiling <= (1.0 - fraction)` is specified here with VP-012 candidacy; `check_watermark_trigger` is the pure-core extraction of this arithmetic, verified by this VP to implement it correctly for all valid bounded inputs.
- **Postcondition 2 (OnWatermark):** `tokens_remaining / budget_ceiling <= (1.0 - fraction)` triggers compaction. `fraction = 0.8` means "trigger when ≥80% consumed (≤20% remaining)". `fraction = 1.0` fires when `tokens_remaining == 0`.
- **Invariant — OnWatermark arithmetic:** The trigger condition is a pure f64 comparison with no side effects. VP-012 (Kani P1, seeded burst-232): returns mathematically correct boolean for all valid inputs.
- **Invariant — DI-014:** Configuration errors (fraction=0.0) propagate as `Err` at construction time; they are not silently treated as `Disabled`.
- **EC-002 (fraction=1.0):** `tokens_remaining/ceiling <= 0.0` fires only when `tokens_remaining == 0`. Consistent with `<=` form; would be unreachable with strict `<`.
- **EC-004:** `tokens_remaining > ceiling` → `tokens_remaining / ceiling > 1.0 > (1 - fraction)` for any `fraction > 0` → condition evaluates false; no spurious trigger.
- **TV-001/002:** `OnWatermark { fraction: 0.8 }`, ceiling=100_000, remaining=19_999 → fires; remaining=20_001 → does not fire.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| Model checking | Kani 0.67.0 | Yes — `tokens_remaining` and `ceiling` bounded to ≤ 2^24 (16,777,216); `fraction` symbolic over valid `f64` range (0.0, 1.0]; proves correct boolean for all bounded inputs | All symbolic `(tokens_remaining, ceiling, fraction)` triples within bounds; proves arithmetic equivalence between the function result and the expected boolean expression |

**Kani async constraint (Kani 0.67.0 has NO native async support):**
`check_watermark_trigger(tokens_remaining: u64, ceiling: u64, fraction: f64) -> bool` is the
pure arithmetic extraction of ADR-019 Decision 3, step 1 — the watermark check
`tokens_remaining / ceiling <= (1.0 - fraction)` — implemented as a standalone pure-core
synchronous function in `pregolya-core::core::budget` per ADR-009 Option 3 (definitions-only
placement; the BudgetEngine in `graph::budget` calls it). No `.await`, no Tokio runtime, no I/O.
The Kani harness proves the function correctly implements this arithmetic for all valid
bounded inputs.

**Bounding rationale for u64 inputs:** Using f64 arithmetic, exact integer representation
holds up to 2^53 (f64 mantissa is 52 bits). The practical bound of 2^24 (16.7M tokens)
is retained for CBMC state-space tractability, not precision necessity. All realistic LLM
context windows as of D23 (Claude max ≈ 200K tokens) fall well within this bound.

**NaN / infinity analysis:** With `ceiling > 0` and `tokens_remaining ≥ 0` (u64; `tokens_remaining ≤ ceiling` enforced), `(tokens_remaining as f64) / (ceiling as f64)` is finite and non-negative (= 0.0 when tokens_remaining = 0, > 0.0 otherwise). With `fraction ∈ (0.0, 1.0]`, `1.0 - fraction ∈ [0.0, 1.0)` — finite. No NaN or infinity is reachable on valid inputs.

**Harness boundary:** The proof covers `check_watermark_trigger` as a standalone pure function.
The `BudgetEngine` in `pregolya-graph::graph::budget` that calls it is effectful and excluded
from the Kani scope. The calling engine's correctness is covered by integration tests.

## Proof Harness Skeleton

Target file: `pregolya-core/src/budget.rs`

```rust
// pregolya-core/src/proofs/watermark.rs
// Target fn: core::budget::check_watermark_trigger

#[cfg(kani)]
mod proofs {
    use super::*;

    /// VP-012: OnWatermark Arithmetic — fires iff tokens_remaining/ceiling <= (1.0 - fraction)
    /// Proves: check_watermark_trigger returns the mathematically correct boolean for all valid inputs.
    #[kani::proof]
    fn watermark_arithmetic_harness() {
        // Bound inputs for tractable CBMC state space
        let tokens_remaining: u64 = kani::any();
        let ceiling: u64 = kani::any();
        let fraction: f64 = kani::any();

        // Valid input preconditions (per BC-2.10.005 §Preconditions, v1.2)
        // tokens_remaining: u64 is always >= 0 by type; the strict > 0 assume is dropped
        // because tokens_remaining = 0 is IN-domain (budget fully consumed, EC-002 boundary).
        kani::assume(ceiling > 0);
        kani::assume(tokens_remaining <= ceiling);
        // Bound to 2^24 for CBMC state-space tractability (16M tokens >> realistic context window)
        kani::assume(ceiling <= 1 << 24);
        // fraction in (0.0, 1.0] — fraction = 0.0 is rejected at construction time (EC-001)
        kani::assume(fraction > 0.0f64);
        kani::assume(fraction <= 1.0f64);
        kani::assume(fraction.is_finite());

        let result = check_watermark_trigger(tokens_remaining, ceiling, fraction);

        // Expected: (tokens_remaining as f64) / (ceiling as f64) <= (1.0 - fraction)
        // Non-strict <= is load-bearing for fraction=1.0/remaining=0 (EC-002).
        let r = tokens_remaining as f64;
        let c = ceiling as f64;
        let expected = r / c <= (1.0f64 - fraction);

        kani::assert(
            result == expected,
            "OnWatermark arithmetic must match the mathematical condition exactly"
        );

        // No NaN or infinity in either value
        kani::assert((r / c).is_finite(), "tokens/ceiling ratio must be finite");
        kani::assert((1.0f64 - fraction).is_finite(), "(1.0 - fraction) must be finite");
    }

    /// Positive: exact boundary — remaining exactly at the watermark FIRES (non-strict <=).
    /// fraction=0.8, remaining/ceiling=0.2 → condition is 0.2 <= 0.2 → true (fires).
    /// This is the CORRECT boundary semantics: "compact when AT LEAST fraction consumed."
    #[kani::proof]
    fn watermark_boundary_fires() {
        // fraction = 0.8 → threshold = 0.2; remaining = 20,000 / ceiling = 100,000 → ratio = 0.2
        let result = check_watermark_trigger(20_000, 100_000, 0.8f64);
        // 0.2 <= 0.2 is true — boundary FIRES with non-strict <=
        kani::assert(result, "remaining exactly at threshold MUST fire (non-strict <=)");
    }

    /// Positive: one token above threshold does NOT fire.
    #[kani::proof]
    fn watermark_one_token_above_does_not_fire() {
        // fraction = 0.8 → threshold = 0.2; remaining = 20,001 / ceiling = 100,000 → 0.20001 > 0.2
        let result = check_watermark_trigger(20_001, 100_000, 0.8f64);
        kani::assert(!result, "remaining one token above threshold MUST NOT fire");
    }

    /// Positive: one token below threshold fires.
    #[kani::proof]
    fn watermark_one_token_below_fires() {
        // fraction = 0.8 → threshold = 0.2; remaining = 19,999 / ceiling = 100,000 → 0.19999 <= 0.2
        let result = check_watermark_trigger(19_999, 100_000, 0.8f64);
        kani::assert(result, "remaining one token below threshold MUST fire");
    }

    /// Positive: fraction=1.0 fires only when tokens_remaining==0 (EC-002).
    #[kani::proof]
    fn watermark_fraction_one_fires_at_zero_remaining() {
        // fraction = 1.0 → threshold = 0.0; remaining = 0 / ceiling = 100,000 → 0.0 <= 0.0
        let result = check_watermark_trigger(0, 100_000, 1.0f64);
        // tokens_remaining=0 is IN-domain (precondition: 0 <= tokens_remaining <= ceiling).
        // Non-strict <=: 0.0 / ceiling = 0.0 <= 0.0 → true. Fires correctly (EC-002).
        kani::assert(result, "fraction=1.0 MUST fire when tokens_remaining==0 (EC-002)");
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded | `tokens_remaining` and `ceiling` ≤ 2^24 (CBMC tractability bound); `fraction` over finite f64 range (0.0, 1.0]; CBMC handles bounded integer + f64 symbolic |
| Proof complexity | Low | The function is 2–3 lines of arithmetic: cast to f64, divide, compare. Single conditional expression. No loops, no branching on content |
| Tool support | Supported | Kani 0.67.0; `check_watermark_trigger` is pure-core sync; f64 arithmetic with finite inputs is well-modeled by Kani's CBMC backend |
| Estimated proof time | 5–15 min | f64 symbolic arithmetic has slightly larger state space than f32 but remains tractable for this simple comparison. Bounded integer range keeps CBMC converging faster than vector-length proofs. |

Key factors:
1. `check_watermark_trigger` is a pure-core synchronous function — no I/O, no async.
   Kani 0.67.0 compatible without any adaptation.
2. The arithmetic is trivial: one division, one subtraction, one comparison. The proof is
   essentially asking CBMC to verify an identity: `f(x) == expr(x)` for bounded `x`. This
   class of proof is highly tractable.
3. Using f64 (not f32), the `as f64` cast from `u64` is exact up to 2^53. The 2^24 bound
   is retained for CBMC state-space tractability, not precision necessity. All realistic
   LLM context windows (Claude max ≈ 200K tokens as of D23) are far below this bound.
4. The non-strict `<=` comparison (vs the former `<`) is equally tractable for CBMC;
   the operator change does not affect proof complexity.

**Known constraint:** The 2^24 tractability bound does not cover token budgets exceeding
16M tokens. If future LLM context windows routinely exceed 16M tokens, this VP must be
amended to expand the bound or reformulate as a pure-integer comparison.

**Blocking risk (NONE):** No async, no complex types, no non-standard Kani patterns. The proof
is a textbook arithmetic equivalence check and is expected to pass in the first iteration.
