# VP-012: OnWatermark Arithmetic — Trigger Fires Iff tokens_remaining / ceiling < (1.0 - fraction); No Overflow; Disabled Never Fires

## Property Statement

For all valid `(tokens_remaining: u64, ceiling: u64, fraction: f32)` tuples where
`0 < tokens_remaining ≤ ceiling` and `fraction ∈ (0.0, 1.0]`, the pure function
`check_watermark_trigger` returns `true` if and only if
`(tokens_remaining as f32) / (ceiling as f32) < (1.0 - fraction)`. `Disabled` never
produces a trigger. No integer overflow or `f32::NAN` arises on any valid input.

**Formal invariant (DI-014):**
```
∀ tokens_remaining: u64, ceiling: u64, fraction: f32:
  0 < tokens_remaining ≤ ceiling  ∧  0.0 < fraction ≤ 1.0  →
    check_watermark_trigger(tokens_remaining, ceiling, fraction)
      == ((tokens_remaining as f32) / (ceiling as f32) < (1.0 - fraction))

∀ fraction: f32, 0.0 < fraction ≤ 1.0:
  (1.0 - fraction) ∈ [0.0, 1.0)          // no NaN; subtraction does not underflow below 0

∀ tokens_remaining: u64, ceiling: u64:
  0 < tokens_remaining ≤ ceiling  →
    (tokens_remaining as f32) / (ceiling as f32) ∈ (0.0, 1.0]  // no NaN; ceiling > 0
```

The `Disabled` variant is never passed to `check_watermark_trigger` (the caller inspects
the variant before calling); the function is only invoked for the `OnWatermark` case. The
proof bounds the integer inputs to a tractable sub-range of u64 to keep CBMC state space
finite while preserving arithmetic generality.

## Source Contract

- **BC:** BC-2.10.005 — CompactionTrigger Configuration — Disabled/OnWatermark/OnMessageCount/OnTokenCount; BudgetConfig Extension; Watermark Arithmetic (VP-012 Kani Seed)
- **Postcondition 2 (OnWatermark):** `tokens_remaining / budget_ceiling < (1.0 - fraction)` triggers compaction. `fraction = 0.8` means "trigger when 80% consumed (20% remaining)".
- **Invariant — OnWatermark arithmetic:** The trigger condition is a pure f32 comparison with no side effects. VP-012 (Kani P1, seeded burst-232): returns mathematically correct boolean for all valid inputs.
- **Invariant — DI-014:** Configuration errors (fraction=0.0) propagate as `Err` at construction time; they are not silently treated as `Disabled`.
- **EC-004:** `tokens_remaining > ceiling` → `tokens_remaining / ceiling > 1.0` → condition evaluates false for any `fraction ≤ 1.0`; no spurious trigger.
- **TV-001/002 (Red Gate):** `OnWatermark { fraction: 0.8 }`, ceiling=100_000, remaining=19_999 → fires; remaining=20_001 → does not fire.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| Model checking | Kani 0.67.0 | Yes — `tokens_remaining` and `ceiling` bounded to ≤ 2^24 (16,777,216); `fraction` symbolic over valid `f32` range (0.0, 1.0]; proves correct boolean for all bounded inputs | All symbolic `(tokens_remaining, ceiling, fraction)` triples within bounds; proves arithmetic equivalence between the function result and the expected boolean expression |

**Kani async constraint (Kani 0.67.0 has NO native async support):**
`check_watermark_trigger(tokens_remaining: u64, ceiling: u64, fraction: f32) -> bool` is a
pure-core synchronous function in `ferrochain-core::core::budget` (definitions-only module,
ADR-019 Decision 1 / ADR-009 Option 3). No `.await`, no Tokio runtime, no I/O. The Kani
harness calls it directly.

**Bounding rationale for u64 inputs:** The `as f32` cast from `u64` loses precision for values
above 2^24 (the f32 mantissa is 23 bits). Above 2^24, consecutive integers may map to the same
`f32` value, and the arithmetic proof becomes a precision-loss analysis rather than a correctness
proof. The bounds `tokens_remaining ≤ 2^24` and `ceiling ≤ 2^24` with `ceiling > 0` cover
100% of practical token-budget scenarios (16M tokens far exceeds realistic LLM context windows
as of D23) while keeping the CBMC state space tractable.

**NaN / infinity analysis:** With `ceiling > 0` and both values finite positive (enforced by
the `tokens_remaining ≤ ceiling` and `ceiling > 0` preconditions), `(tokens_remaining as f32) / (ceiling as f32)` is finite and positive. With `fraction ∈ (0.0, 1.0]`, `1.0 - fraction ∈ [0.0, 1.0)` — finite. No NaN or infinity is reachable on valid inputs.

**Harness boundary:** The proof covers `check_watermark_trigger` as a standalone pure function.
The `BudgetEngine` in `ferrochain-graph::graph::budget` that calls it is effectful and excluded
from the Kani scope. The calling engine's correctness is covered by integration tests.

## Proof Harness Skeleton

Target file: `ferrochain-core/src/budget.rs` (or `ferrochain-core/src/core/budget.rs`)

```rust
// ferrochain-core/src/proofs/watermark_arithmetic.rs
// Target fn: core::budget::check_watermark_trigger

#[cfg(kani)]
mod proofs {
    use super::*;

    /// VP-012: OnWatermark Arithmetic — fires iff tokens_remaining/ceiling < (1.0 - fraction)
    /// Proves: check_watermark_trigger returns the mathematically correct boolean for all valid inputs.
    #[kani::proof]
    fn watermark_arithmetic_harness() {
        // Bound inputs for tractable CBMC state space
        let tokens_remaining: u64 = kani::any();
        let ceiling: u64 = kani::any();
        let fraction: f32 = kani::any();

        // Valid input preconditions (per BC-2.10.005 §Preconditions)
        kani::assume(tokens_remaining > 0);
        kani::assume(ceiling > 0);
        kani::assume(tokens_remaining <= ceiling);
        // Bound to 2^24 for f32 precision tractability (16M tokens >> realistic context window)
        kani::assume(ceiling <= 1 << 24);
        kani::assume(tokens_remaining <= ceiling);  // ensures tokens_remaining <= 2^24 transitively
        // fraction in (0.0, 1.0] — fraction = 0.0 is rejected at construction time (EC-001)
        kani::assume(fraction > 0.0f32);
        kani::assume(fraction <= 1.0f32);
        kani::assume(fraction.is_finite());

        let result = check_watermark_trigger(tokens_remaining, ceiling, fraction);

        // Expected: (tokens_remaining as f32) / (ceiling as f32) < (1.0 - fraction)
        let r = tokens_remaining as f32;
        let c = ceiling as f32;
        let expected = r / c < (1.0f32 - fraction);

        kani::assert(
            result == expected,
            "OnWatermark arithmetic must match the mathematical condition exactly"
        );

        // No NaN or infinity in either value
        kani::assert((r / c).is_finite(), "tokens/ceiling ratio must be finite");
        kani::assert((1.0f32 - fraction).is_finite(), "(1.0 - fraction) must be finite");
    }

    /// Positive: exact boundary — remaining at exactly the watermark does NOT fire.
    /// fraction=0.8, remaining/ceiling=0.2 → condition is 0.2 < 0.2 → false (no trigger).
    #[kani::proof]
    fn watermark_boundary_does_not_fire() {
        // fraction = 0.8 → threshold = 0.2; remaining = 20,000 / ceiling = 100,000 → ratio = 0.2
        let result = check_watermark_trigger(20_000, 100_000, 0.8f32);
        // 0.2 < 0.2 is false — boundary does NOT fire
        // Note: f32 precision — 20_000 / 100_000 == 0.2 exactly for these small integers
        kani::assert(!result, "remaining exactly at threshold MUST NOT fire");
    }

    /// Positive: one token below threshold fires.
    #[kani::proof]
    fn watermark_one_token_below_fires() {
        // fraction = 0.8 → threshold = 0.2; remaining = 19,999 / ceiling = 100,000 → 0.19999 < 0.2
        let result = check_watermark_trigger(19_999, 100_000, 0.8f32);
        kani::assert(result, "remaining one token below threshold MUST fire");
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded | `tokens_remaining` and `ceiling` ≤ 2^24 (f32 precision boundary); `fraction` over finite f32 range (0.0, 1.0]; CBMC handles bounded integer + f32 symbolic |
| Proof complexity | Low | The function is 2–3 lines of arithmetic: cast to f32, divide, compare. Single conditional expression. No loops, no branching on content |
| Tool support | Supported | Kani 0.67.0; `check_watermark_trigger` is pure-core sync; f32 arithmetic with finite inputs is well-modeled by Kani's CBMC backend |
| Estimated proof time | 3–10 min | Bounded integer range with f32 symbolic arithmetic; CBMC converges faster than vector-length proofs (VP-009 pattern) because there are no loops |

Key factors:
1. `check_watermark_trigger` is a pure-core synchronous function — no I/O, no async.
   Kani 0.67.0 compatible without any adaptation.
2. The arithmetic is trivial: one division, one subtraction, one comparison. The proof is
   essentially asking CBMC to verify an identity: `f(x) == expr(x)` for bounded `x`. This
   class of proof is highly tractable.
3. The 2^24 bound preserves the proof's engineering validity: all realistic token budgets
   (Claude max context ≈ 200K tokens as of D23) are well within the f32 precision range.
   The proof covers 100% of intended usage.

**Known constraint:** The `as f32` cast from `u64` is lossy above 2^24. Kani cannot prove the
full u64 range without triggering precision-loss cases. The 2^24 bound is documented in the
proof harness comment. If future token budgets exceed 16M tokens, this VP must be amended to
either use f64 arithmetic or a different comparison mechanism.

**Blocking risk (NONE):** No async, no complex types, no non-standard Kani patterns. The proof
is a textbook arithmetic equivalence check and is expected to pass in the first iteration.
