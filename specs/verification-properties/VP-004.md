# VP-004: MCP ToolException Type-Identity Preservation

## Property Statement

When an MCP server raises a bare `ToolException`, the ferrochain MCP adapter re-raises it
as an `MCP ToolException` error preserving exact type identity. The error type is not
downcast, wrapped in a generic error, or silently converted to a string error.

**Invariant (DI-014):** MCP tool errors propagate as `Err(FerrochainError { code: "E-MCP-001", ... })`
with the original exception type information preserved in the error source chain.

| BC | Title |

## Verification Strategy

**Tool:** Integration test (behavioral — not Kani-tractable; involves I/O transport)

Red Gate test: `tests/red_gate/test_BC_2_09_004_mcp_tool_exception.rs`

Test scenario: mock MCP server that raises a bare `ToolException`; assert that the
ferrochain adapter surfaces `Err(FerrochainError { code: "E-MCP-001", ... })` with
the original exception type accessible via `error.source()`.

## Feasibility Assessment

**Feasibility: HIGH.** This is a behavioral test, not a formal proof. The property is
verified by constructing a mock MCP server that raises known exception types and asserting
the adapter's error handling preserves the type chain.

**Phase 6 consideration:** No Kani harness planned. Red Gate integration test is sufficient.
