# VP-008: Embeddings Dimensionality Contract — All Batch Vectors Equal-Length; embed_query Length Matches embed_documents Inner Length

## Property Statement

For any valid `Embeddings` implementation, all inner vectors returned by `embed_documents`
have the same length `d`, and the vector returned by `embed_query` has the same length `d`.
Batches with inconsistent inner lengths, count mismatches, or zero-length vectors are not
silently returned — they produce `Err(E-EMBED-001)`.

**Formal invariant (DI-014):**
```
∀ impl T: Embeddings, ∀ texts: Vec<String> with texts.len() ≥ 1:
  T::embed_documents(texts) → Ok(vecs) →
    vecs.len() == texts.len()
    ∧ ∀ v ∈ vecs: v.len() == d (all equal, d > 0)
    ∧ T::embed_query(texts[0]) → Ok(q) → q.len() == d

∀ impl T: Embeddings:
  T::embed_documents(vec![]) → Ok(vec![])   — empty input → empty output, no error
```

No valid `Embeddings` implementation may return `Ok(vecs)` where `vecs` contains vectors of
differing lengths, or where `vecs.len() != texts.len()` — these violations must be caught
and returned as `Err(E-EMBED-001)`.

## Source Contract

- **BC:** BC-2.22.001 — Embeddings Trait — embed_documents Batch; embed_query; Dimensionality Contract → E-EMBED-001; Batch Partial-Failure as Err; Arc<dyn Embeddings> Dyn-Safe (VP-008 Proptest Seed)
- **Invariant 1:** One vector per input — `embed_documents(texts).ok().map(|v| v.len()) == Some(texts.len())`.
- **Invariant 2:** Consistent inner length — for any `Ok(vecs)`, all `vecs[i].len()` are equal.
- **Invariant 3:** `embed_query` length equals `embed_documents` inner length for the same model/config.
- **Postcondition 2 partial:** Provider-inconsistent batches return `Err(E-EMBED-001)` (detected before returning).
- **EC-001:** `embed_documents(vec![])` → `Ok(vec![])` — empty input is not an error.
- **EC-003:** Provider returning 9 vectors for 10 inputs → `Err(E-EMBED-001)`.
- **EC-004:** Provider returning a zero-length vector → `Err(E-EMBED-001)`.

**Proptest strategy — production validator under test:**

This VP targets `validate_embedding_batch`, a PRODUCTION FUNCTION in `core::embeddings`
that encodes the dimensionality contract. All `Embeddings` implementations must call this
validator before returning batch results. The mock impls supply raw outputs (correct or
invalid) as INPUTS to the validator; no validation logic lives inside the mocks.

**Why this design prevents self-proving mocks:**
- Old design: mock impl contained the validation gate internally → assertions tested mock
  behavior, not production code. A deleted production validator would leave all tests green.
- New design: mocks return raw vectors unconditionally; every assertion calls
  `validate_embedding_batch(texts, vecs)` (production code). If the production validator
  is removed or regresses, tests fail.

Property families:
1. **Positive (VP-008-A):** Valid mock output → `validate_embedding_batch` returns `Ok(())`.
2. **Positive (VP-008-B):** Empty input → `validate_embedding_batch` returns `Ok(())`.
3. **Negative (VP-008-C, Invariant 2):** Ragged inner lengths → `Err(E-EMBED-001)`.
4. **Negative (VP-008-D, EC-003):** Count mismatch → `Err(E-EMBED-001)`.
5. **Negative (VP-008-E, EC-004):** Zero-length inner vector → `Err(E-EMBED-001)`.

**Production function specification:**

```rust
// pregolya-core/src/embeddings.rs — production code (NOT test-only)
/// Validates that a batch of embedding vectors satisfies the dimensionality contract.
/// Must be called by all `Embeddings` impls before returning Ok from `embed_documents`.
///
/// Returns `Err(E-EMBED-001)` on any of:
///   - `vecs.len() != texts.len()` (EC-003: count mismatch)
///   - any `vecs[i].len() == 0` (EC-004: zero-length embedding)
///   - inconsistent inner lengths across `vecs` (Invariant 2)
pub fn validate_embedding_batch(
    texts: &[String],
    vecs: &[Vec<f32>],
) -> Result<(), PregolyaError> {
    // EC-003: count mismatch
    if vecs.len() != texts.len() {
        return Err(PregolyaError::new(
            Component::Embed,
            Category::Val,
            RetryHint::Never,
            "E-EMBED-001",
            format!(
                "EmbeddingDimensionMismatch: expected {} vectors for {} inputs, got {}",
                texts.len(), texts.len(), vecs.len()
            ),
        ));
    }
    if vecs.is_empty() {
        return Ok(());  // EC-001: empty input is not an error
    }
    let first_len = vecs[0].len();
    // EC-004: zero-length first vector
    if first_len == 0 {
        return Err(PregolyaError::new(
            Component::Embed,
            Category::Val,
            RetryHint::Never,
            "E-EMBED-001",
            "EmbeddingDimensionMismatch: embedding vector has zero length",
        ));
    }
    for v in vecs.iter().skip(1) {
        // EC-004: zero-length subsequent vector
        if v.is_empty() {
            return Err(PregolyaError::new(
                Component::Embed,
                Category::Val,
                RetryHint::Never,
                "E-EMBED-001",
                "EmbeddingDimensionMismatch: embedding vector has zero length",
            ));
        }
        // Invariant 2: inconsistent inner length
        if v.len() != first_len {
            return Err(PregolyaError::new(
                Component::Embed,
                Category::Val,
                RetryHint::Never,
                "E-EMBED-001",
                "EmbeddingDimensionMismatch: embedding batch returned inconsistent vector lengths",
            ));
        }
    }
    Ok(())
}
```

**Why proptest and not Kani:** `embed_documents` and `embed_query` are `async` methods
(ADR-017 Decision 2: `#[async_trait]` desugaring). Kani 0.67.0 has NO native async support;
calling `.await` in a harness fails verification. However, `validate_embedding_batch` is a
PURE SYNC function (no I/O, no async) — it is a Kani candidate for the arithmetic invariants.
Proptest covers the behavioral property over random batch sizes; `validate_embedding_batch`
purity makes it independently verifiable by Kani in Phase 6.

```rust
// pregolya-core/src/embeddings.rs — within #[cfg(test)] mod tests

#[cfg(test)]
mod tests {
    use super::*;
    use proptest::prelude::*;

    /// Mock Embeddings: returns raw uniform-length vectors (no internal validation).
    /// This mock DOES NOT contain the validation gate — validate_embedding_batch
    /// (production code) is called explicitly in each harness.
    struct RawMockEmbeddings { dim: usize }

    #[async_trait]
    impl Embeddings for RawMockEmbeddings {
        async fn embed_documents(&self, texts: Vec<String>) -> Result<Vec<Vec<f32>>, PregolyaError> {
            // Returns raw valid-length vectors; validation is NOT performed internally.
            // Production embed_documents impls must call validate_embedding_batch before
            // returning — this mock intentionally omits that call for harness isolation.
            let vecs: Vec<Vec<f32>> = texts.iter().map(|_| vec![0.1f32; self.dim]).collect();
            Ok(vecs)
        }
        async fn embed_query(&self, _text: String) -> Result<Vec<f32>, PregolyaError> {
            Ok(vec![0.1f32; self.dim])
        }
    }

    proptest! {
        /// VP-008-A: validate_embedding_batch accepts a valid batch.
        /// Tests the PRODUCTION validator, not the mock.
        /// Assertion can FAIL if validate_embedding_batch is removed or regresses.
        #[test]
        fn prop_validate_embedding_batch_accepts_valid(
            dim in 1usize..=4096usize,
            n_texts in 1usize..=64usize,
        ) {
            let texts: Vec<String> = (0..n_texts).map(|i| format!("text {i}")).collect();
            let vecs: Vec<Vec<f32>> = (0..n_texts).map(|_| vec![0.1f32; dim]).collect();

            // PRODUCTION CODE UNDER TEST: validate_embedding_batch
            let result = validate_embedding_batch(&texts, &vecs);

            prop_assert!(result.is_ok(), "valid batch must pass production validator; dim={dim}, n={n_texts}");
        }

        /// VP-008-B: validate_embedding_batch accepts empty input (EC-001).
        #[test]
        fn prop_validate_embedding_batch_accepts_empty(dim in 1usize..=512usize) {
            let _ = dim; // dim irrelevant for empty-input test
            let texts: Vec<String> = vec![];
            let vecs: Vec<Vec<f32>> = vec![];

            // PRODUCTION CODE UNDER TEST: validate_embedding_batch
            let result = validate_embedding_batch(&texts, &vecs);

            prop_assert!(result.is_ok(), "empty input must return Ok(()) per EC-001");
        }
    }

    /// VP-008-C: ragged inner lengths (Invariant 2 violation) → Err(E-EMBED-001).
    /// Mock returns raw inconsistent vectors; production validator must catch the violation.
    #[test]
    fn ragged_batch_rejected_by_production_validator() {
        // Mock returns raw ragged output WITHOUT any internal validation.
        // The production validate_embedding_batch must detect the violation.
        let texts = vec!["a".to_string(), "b".to_string()];
        let vecs = vec![
            vec![0.1f32; 768],  // length 768
            vec![0.1f32; 512],  // length 512 — violates Invariant 2
        ];

        // PRODUCTION CODE UNDER TEST: validate_embedding_batch
        let result = validate_embedding_batch(&texts, &vecs);

        assert!(
            matches!(result, Err(ref e) if e.code == "E-EMBED-001"),
            "ragged batch must be rejected by production validator with E-EMBED-001"
        );
    }

    /// VP-008-D: count mismatch (EC-003) — provider returns fewer vectors than inputs.
    /// Validates that validate_embedding_batch catches vecs.len() != texts.len().
    #[test]
    fn count_mismatch_rejected_by_production_validator() {
        let texts = vec!["a".to_string(), "b".to_string(), "c".to_string()]; // 3 inputs
        let vecs = vec![
            vec![0.1f32; 768],  // only 2 vectors returned for 3 inputs
            vec![0.1f32; 768],
        ];

        // PRODUCTION CODE UNDER TEST: validate_embedding_batch
        let result = validate_embedding_batch(&texts, &vecs);

        assert!(
            matches!(result, Err(ref e) if e.code == "E-EMBED-001"),
            "count mismatch (3 inputs, 2 vectors) must be rejected with E-EMBED-001 (EC-003)"
        );
    }

    /// VP-008-E: zero-length inner vector (EC-004) → Err(E-EMBED-001).
    /// Validates that validate_embedding_batch catches zero-dimension embeddings.
    #[test]
    fn zero_length_vector_rejected_by_production_validator() {
        let texts = vec!["a".to_string(), "b".to_string()];
        let vecs = vec![
            vec![0.1f32; 768],  // valid length
            vec![],             // zero-length — EC-004 violation
        ];

        // PRODUCTION CODE UNDER TEST: validate_embedding_batch
        let result = validate_embedding_batch(&texts, &vecs);

        assert!(
            matches!(result, Err(ref e) if e.code == "E-EMBED-001"),
            "zero-length vector must be rejected by production validator with E-EMBED-001 (EC-004)"
        );
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Unbounded via proptest | Random `(dim, n_texts)` pairs; proptest shrinks counterexamples |
| Proof complexity | Low | Vec length comparisons; no complex algorithms |
| Tool support | Supported | proptest 1.x; `validate_embedding_batch` is pure sync — no async runtime needed |
| Estimated proof time | < 10s | Simple Vec length assertions against a pure sync production function |

Key factors:
1. `validate_embedding_batch` is a pure sync function (no I/O, no async). The proptest
   harness calls it directly without any Tokio runtime — no `block_on` needed for VP-008-A/B.
   The concrete harnesses (VP-008-C/D/E) also call it directly.
2. The dimensionality contract is a structural property of `Vec<f32>` lengths — proptest's
   integer range generation (`dim: 1..=4096, n_texts: 1..=64`) covers the critical boundary cases.
3. The negative-case tests (VP-008-C, VP-008-D, VP-008-E) are concrete (not proptest) because
   each input is a deterministic violation — proptest is not needed for deterministic negative cases.
4. `validate_embedding_batch` purity makes it a Kani candidate for Phase 6 formal hardening
   (bounded exhaustive proof over `usize` counts; the async `embed_documents`/`embed_query`
   methods remain proptest-only due to Kani 0.67.0 async constraint).
