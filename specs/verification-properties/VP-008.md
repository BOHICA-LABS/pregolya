# VP-008: Embeddings Dimensionality Contract — All Batch Vectors Equal-Length; embed_query Length Matches embed_documents Inner Length

## Property Statement

For any valid `Embeddings` implementation, all inner vectors returned by `embed_documents`
have the same length `d`, and the vector returned by `embed_query` has the same length `d`.
Batches with inconsistent inner lengths, count mismatches, or zero-length vectors are not
silently returned — they produce `Err(E-EMBED-001)`.

**Formal invariant (DI-014):**
```
∀ impl T: Embeddings, ∀ texts: Vec<String> with texts.len() ≥ 1:
  T::embed_documents(texts) → Ok(vecs) →
    vecs.len() == texts.len()
    ∧ ∀ v ∈ vecs: v.len() == d (all equal, d > 0)
    ∧ T::embed_query(texts[0]) → Ok(q) → q.len() == d

∀ impl T: Embeddings:
  T::embed_documents(vec![]) → Ok(vec![])   — empty input → empty output, no error
```

No valid `Embeddings` implementation may return `Ok(vecs)` where `vecs` contains vectors of
differing lengths, or where `vecs.len() != texts.len()` — these violations must be caught
and returned as `Err(E-EMBED-001)`.

## Source Contract

- **BC:** BC-2.22.001 — Embeddings Trait — embed_documents Batch; embed_query; Dimensionality Contract → E-EMBED-001; Batch Partial-Failure as Err; Arc<dyn Embeddings> Dyn-Safe (VP-008 Proptest Seed)
- **Invariant 1:** One vector per input — `embed_documents(texts).ok().map(|v| v.len()) == Some(texts.len())`.
- **Invariant 2:** Consistent inner length — for any `Ok(vecs)`, all `vecs[i].len()` are equal.
- **Invariant 3:** `embed_query` length equals `embed_documents` inner length for the same model/config.
- **Postcondition 2 partial:** Provider-inconsistent batches return `Err(E-EMBED-001)` (detected before returning).
- **EC-001:** `embed_documents(vec![])` → `Ok(vec![])` — empty input is not an error.
- **EC-003:** Provider returning 9 vectors for 10 inputs → `Err(E-EMBED-001)`.
- **EC-004:** Provider returning a zero-length vector → `Err(E-EMBED-001)`.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| Property-based testing | proptest | N/A — random inputs | For any mock `Embeddings` impl with configurable dimension `d`: generate random `Vec<String>` inputs; assert `vecs.len() == texts.len()`; assert all `vecs[i].len() == d`; assert `embed_query` length == `d`; assert empty-input returns `Ok(vec![])` |

**Proptest strategy — mock Embeddings impl:**

The proptest harness uses a `MockEmbeddings { dim: usize }` that correctly implements the
dimensionality contract, and a `RaggedMockEmbeddings` that deliberately violates it (returns
inconsistent inner lengths) to verify that `Err(E-EMBED-001)` is produced. Two property
families:

1. **Positive properties:** `MockEmbeddings` with valid `dim > 0` — assert all invariants hold.
2. **Negative properties:** `RaggedMockEmbeddings` — assert invariants 1/2 violations produce `Err(E-EMBED-001)`.

**Why proptest and not Kani:** `embed_documents` and `embed_query` are `async` methods
(ADR-017 Decision 2: `#[async_trait]` desugaring). Kani 0.67.0 has NO native async support;
calling `.await` in a harness fails verification. The dimensionality invariants are behavioral
contracts about `Vec<f32>` lengths — proptest covers this class of property effectively
via random text batches, and the mock impl eliminates the async I/O concern by running
synchronously under Tokio's `block_on` in the proptest harness.

## Proof Harness Skeleton

Target file: `ferrochain-core/src/embeddings.rs` (proptest cases in `#[cfg(test)] mod tests`)

```rust
// ferrochain-core/src/embeddings.rs — within #[cfg(test)] mod tests

#[cfg(test)]
mod tests {
    use super::*;
    use proptest::prelude::*;

    /// Mock Embeddings: always returns correct dim-length vectors (happy path)
    struct MockEmbeddings { dim: usize }

    #[async_trait]
    impl Embeddings for MockEmbeddings {
        async fn embed_documents(&self, texts: Vec<String>) -> Result<Vec<Vec<f32>>, FerrochainError> {
            Ok(texts.iter().map(|_| vec![0.1f32; self.dim]).collect())
        }
        async fn embed_query(&self, _text: String) -> Result<Vec<f32>, FerrochainError> {
            Ok(vec![0.1f32; self.dim])
        }
    }

    proptest! {
        /// VP-008-A: one vector per input; all vectors same length; embed_query matches
        #[test]
        fn prop_dimensionality_contract_holds(
            dim in 1usize..=4096usize,
            n_texts in 1usize..=64usize,
        ) {
            let emb = MockEmbeddings { dim };
            let texts: Vec<String> = (0..n_texts).map(|i| format!("text {}", i)).collect();

            let rt = tokio::runtime::Builder::new_current_thread().build().unwrap();
            let vecs = rt.block_on(emb.embed_documents(texts.clone())).unwrap();
            let query_vec = rt.block_on(emb.embed_query("query".to_string())).unwrap();

            // Invariant 1: one vector per input
            prop_assert_eq!(vecs.len(), n_texts);

            // Invariant 2: all inner vectors same length
            prop_assert!(vecs.iter().all(|v| v.len() == dim));

            // Invariant 3: embed_query length == embed_documents inner length
            prop_assert_eq!(query_vec.len(), dim);
        }

        /// VP-008-B: empty input → Ok(vec![])
        #[test]
        fn prop_empty_input_returns_empty_ok(dim in 1usize..=512usize) {
            let emb = MockEmbeddings { dim };
            let rt = tokio::runtime::Builder::new_current_thread().build().unwrap();
            let result = rt.block_on(emb.embed_documents(vec![])).unwrap();
            prop_assert_eq!(result.len(), 0);
        }
    }

    /// VP-008-C: ragged batch (variant lengths) detected → Err(E-EMBED-001)
    #[test]
    fn ragged_batch_returns_embed_error() {
        // An impl that violates invariant 2: returns vectors of different lengths
        struct RaggedEmbeddings;
        #[async_trait]
        impl Embeddings for RaggedEmbeddings {
            async fn embed_documents(&self, texts: Vec<String>) -> Result<Vec<Vec<f32>>, FerrochainError> {
                // Deliberately return ragged output: lengths 768, 512, 768, ...
                let vecs: Vec<Vec<f32>> = texts.iter().enumerate()
                    .map(|(i, _)| if i % 2 == 0 { vec![0.1f32; 768] } else { vec![0.1f32; 512] })
                    .collect();
                // The impl MUST check for ragged output and return Err
                // This test verifies the validation gate inside the impl
                let first_len = vecs[0].len();
                if vecs.iter().any(|v| v.len() != first_len) {
                    return Err(FerrochainError {
                        component: Component::EMBED,
                        category: Category::VALIDATION,
                        code: "E-EMBED-001",
                        message: "EmbeddingDimensionMismatch: embedding batch returned inconsistent vector lengths",
                    });
                }
                Ok(vecs)
            }
            async fn embed_query(&self, _text: String) -> Result<Vec<f32>, FerrochainError> {
                Ok(vec![0.1f32; 768])
            }
        }

        let emb = RaggedEmbeddings;
        let rt = tokio::runtime::Builder::new_current_thread().build().unwrap();
        let texts = vec!["a".to_string(), "b".to_string()];
        let result = rt.block_on(emb.embed_documents(texts));

        assert!(
            matches!(result, Err(FerrochainError { code: "E-EMBED-001", .. })),
            "ragged batch must return E-EMBED-001"
        );
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Unbounded via proptest | Random `(dim, n_texts)` pairs; proptest shrinks counterexamples |
| Proof complexity | Low | Vec length comparisons; no complex algorithms |
| Tool support | Supported | proptest 1.x; tokio `block_on` wraps async calls in proptest harness |
| Estimated proof time | < 10s | Simple Vec length assertions; mock impl is synchronous under `block_on` |

Key factors:
1. The mock `Embeddings` impl eliminates network I/O and `async` runtime concerns. `block_on`
   wraps the async call in proptest without spawning a multi-threaded runtime.
2. The dimensionality contract is a structural property of `Vec<f32>` lengths — proptest's
   integer range generation (`dim: 1..=4096, n_texts: 1..=64`) covers the critical boundary cases.
3. The ragged-batch test is a concrete (not proptest) test because the "violating impl"
   is deterministic — proptest is not needed for deterministic negative cases.

**Async constraint note:** `embed_documents` and `embed_query` are `async` (Kani-incompatible).
Proptest + `tokio::block_on` is the correct verification approach for behavioral invariants on
async trait methods. The proptest harness uses `current_thread` runtime to avoid spawning
extra threads in the test process.
