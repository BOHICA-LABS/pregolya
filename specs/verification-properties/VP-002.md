# VP-002: Session Triple-Address Uniqueness

## Property Statement

Every state operation is addressed by the triple (thread_id, checkpoint_ns, checkpoint_id).
No two distinct triples map to the same storage address. The triple flows from the trait
method signature to the SQL WHERE clause without collapsing.

**Formal invariant (DI-005):** `∀ s1 ≠ s2: SessionKey, storage_address(s1) ≠ storage_address(s2)`

## Source Contract

- **BC:** BC-2.04.006 — Session triple-address uniqueness (thread_id, checkpoint_ns, checkpoint_id)
- **Postcondition/Invariant:** Invariant 1 — the triple `(thread_id, checkpoint_ns, checkpoint_id)` is the composite primary key in every backend schema; no backend may use bare `checkpoint_id` as a sole primary key.
- **Secondary BCs (partial coverage):**
  - BC-2.04.003 Inv1/Inv4: monotonic `checkpoint_id` is unique across the durable store (cross-restart monotonicity preserved via persisted-max seeding per ADR-005 rev-2); the third key of the triple is never reused after a process restart.
  - BC-2.04.004: fork creates a new `CheckpointId` via `get_next_version`; no two fork siblings share the same address triple.

## BC Traceability

| BC | Title | Contribution |
|----|-------|-------------|
| BC-2.04.006 | Session triple-address uniqueness (thread_id, checkpoint_ns, checkpoint_id) | Primary VP obligation |

## Proof Harness Skeleton

Target file: `ferrochain-checkpoint/src/session_index.rs`

```rust
#[cfg(kani)]
mod proofs {
    use super::*;

    /// VP-002: Session Triple-Address Uniqueness
    /// Proves: no two distinct SessionKeys produce the same storage address.
    #[kani::proof]
    fn session_tenancy_harness() {
        let s1: SessionKey = kani::any();
        let s2: SessionKey = kani::any();

        // Bound string fields to keep state space finite (Kani 0.67.0 constraint)
        kani::assume(s1.thread_id.len() <= 64);
        kani::assume(s1.checkpoint_ns.len() <= 64);
        kani::assume(s2.thread_id.len() <= 64);
        kani::assume(s2.checkpoint_ns.len() <= 64);

        // If the keys differ, their addresses must differ
        kani::assume(s1 != s2);

        let addr1 = storage_address(&s1);
        let addr2 = storage_address(&s2);

        kani::assert(addr1 != addr2, "Distinct session keys must map to distinct addresses");
    }

    /// Negative invariant: bare thread_id alone does not address state
    #[kani::proof]
    fn no_bare_thread_id_addressing() {
        let thread_id: ThreadId = kani::any();
        let ns1: CheckpointNamespace = kani::any();
        let ns2: CheckpointNamespace = kani::any();
        let id1: CheckpointId = kani::any();
        let id2: CheckpointId = kani::any();

        // Bound string fields
        kani::assume(thread_id.len() <= 64);
        kani::assume(ns1.len() <= 64);
        kani::assume(ns2.len() <= 64);

        // Two different full triples sharing the same thread_id
        let s1 = SessionKey { thread_id: thread_id.clone(), checkpoint_ns: ns1, checkpoint_id: id1 };
        let s2 = SessionKey { thread_id: thread_id.clone(), checkpoint_ns: ns2, checkpoint_id: id2 };

        kani::assume(s1 != s2); // different full triples

        // Their addresses must still differ (ns or id differs)
        let addr1 = storage_address(&s1);
        let addr2 = storage_address(&s2);

        kani::assert(addr1 != addr2, "Same thread_id but different ns/id must have different addresses");
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded | `ThreadId` and `CheckpointNamespace` constrained to ≤ 64 bytes; `CheckpointId` is `u64` — symbolic but finite |
| Proof complexity | Low | Simple injection check: if inputs differ, outputs differ. No unbounded loops. |
| Tool support | Supported | Kani 0.67.0; `SessionKey` is a plain struct; `kani::Arbitrary` derivable |
| Estimated proof time | < 60s | Per CI budget; injection proofs on bounded structs converge quickly |

Key factors:
1. `storage_address` is a pure function: `SessionKey → StorageAddress` (e.g., a composite SQL primary key tuple).
2. `SessionKey` is a plain struct over bounded symbolic values; `kani::Arbitrary` derivable.
3. The proof is a simple injection check: if inputs differ, outputs differ. No unbounded loops.
4. `CheckpointId` is `u64` (ADR-005 rev-2), `ThreadId` is a bounded string, `CheckpointNamespace` is a bounded string.

**Key insight:** `storage_address` maps the triple to a SQL composite key. The proof guarantees
that the mapping is injective — a property of the address function itself, not the database.
The database PRIMARY KEY constraint enforces uniqueness at runtime; Kani proves the address
function is injective by construction. Cross-restart uniqueness follows from ADR-005 rev-2:
`get_next_version(current, channel)` sources `current` from the persisted `CheckpointTuple`,
so post-restart IDs are always strictly greater than the pre-restart maximum.
