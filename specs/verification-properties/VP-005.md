# VP-005: MultiServerMcpClient Holds No Live Connections

## Property Statement

A `MultiServerMcpClient` instance, after construction and before any tool invocation,
holds zero live connections to MCP servers. Connections are established lazily at
invocation time and not pooled or persisted across calls.

**Invariant (DI-014):** After `MultiServerMcpClient::new(configs)` returns, no network
connections are held. The client is a configuration object, not a live connection pool.

## Source Contract

- **BC:** BC-2.09.005 — MultiServerMcpClient Holds No Live Connections (Red Gate — R11)
- **Postcondition/Invariant:** Postcondition 1 — immediately after construction, no network connections are open (no TCP sockets, no spawned stdio processes, no HTTP sessions are alive); Postcondition 6 — a `MultiServerMcpClient` instance that is dropped without calling any methods causes ZERO network I/O and ZERO async executor interaction; Invariant — the struct is a value type (config bag), not a resource type (connection handle).

## Proof Harness Skeleton

**Tool:** Integration test (behavioral — not Kani-tractable; involves network state)

Red Gate test: `tests/red_gate/test_BC_2_09_005_mcp_no_live_connections.rs`

Test scenario: construct `MultiServerMcpClient` with valid configs pointing to mock
servers; assert that no TCP connections exist immediately after construction (verified
via port inspection or connection count); invoke a tool and assert a connection is
established; after invocation, assert connection is closed (if not pooled).

```rust
// tests/red_gate/test_BC_2_09_005_mcp_no_live_connections.rs
// Red Gate: must compile and FAIL before implementation (test compiles and runs but
// network-I/O assertion inside it fails — struct accidentally initiates connection)

#[tokio::test]
async fn bc_2_09_005_construction_holds_no_connections() {
    let transport = InstrumentedMockTransport::new(); // tracks connection events
    let connections = HashMap::from([
        ("math".to_string(), Connection::mock(transport.clone())),
    ]);

    let client = MultiServerMcpClient::new(connections);

    // Assert: zero connections opened during construction
    assert_eq!(transport.connection_count(), 0, "construction must not open connections");

    // Drop the client — assert no teardown I/O
    drop(client);
    assert_eq!(transport.network_io_events(), 0, "drop must cause zero network I/O");
}

#[tokio::test]
async fn bc_2_09_005_session_creates_and_drops_connection_per_call() {
    let transport = InstrumentedMockTransport::new();
    let connections = HashMap::from([
        ("math".to_string(), Connection::mock(transport.clone())),
    ]);
    let client = MultiServerMcpClient::new(connections);

    // First invocation: connection opens and closes
    {
        let _guard = client.session("math").await.unwrap();
        assert_eq!(transport.connection_count(), 1);
    } // guard dropped: connection must close
    assert_eq!(transport.open_connections(), 0, "connection must close on guard drop");

    // Second invocation: fresh connection, not reused
    {
        let _guard = client.session("math").await.unwrap();
        assert_eq!(transport.connection_count(), 2, "second call creates a new connection");
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH.** This is a behavioral test verifying connection lifecycle semantics.
The property is verified by inspecting connection state (OS-level or via mock transport)
before and after client construction and invocation.

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded | Mock transport; controlled connection events |
| Proof complexity | Low | Assertion on connection count before and after construction/drop |
| Tool support | Supported | cargo nextest; instrumented mock transport |
| Estimated proof time | < 5s | Integration test; no external services |

**R11 context:** The upstream MCP adapter's `__aenter__` `NotImplementedError` contract
(Python async context manager) is the counter-example. Rust's lazy-connection model avoids
this class of issue by making connection establishment explicit at the call site.
