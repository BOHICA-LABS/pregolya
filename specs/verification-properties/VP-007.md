# VP-007: LcSerializable Round-Trip — deserialize(serialize(x)) ≡ x for All Registered Types

## Property Statement

For any type `T` implementing `LcSerializable` with `is_lc_serializable() → true`, the
round-trip `Reviver::revive(T::serialize(&x)) ≡ x` holds: the deserialized value is
semantically equivalent to the original under the type's equivalence relation.

**Formal invariant (DI-008):** `∀ x: T where T: LcSerializable + is_lc_serializable(),
  Reviver::revive(T::serialize(&x)) == Ok(v) ∧ v ≡ x`

The invariant has three components:
1. `T::serialize(&x)` produces `Serialized::Constructor { lc: 1, id: T::lc_id(), kwargs }`.
2. `Reviver::revive(serialized)` returns `Ok(boxed_v)` (id is registered; kwargs are valid).
3. The downcast `boxed_v` is semantically equivalent to `x` under `T`'s PartialEq relation.

Round-trip determinism (BC-2.19.001 Invariant 4): calling serialize→deserialize twice on
the same value produces the same result. No random state or timestamp is injected into kwargs.

## Source Contract

- **BC:** BC-2.19.001 — LcSerializable Round-Trip — Serialize to Serialized::Constructor, Deserialize to Semantically Equivalent Value
- **Postcondition 3:** The deserialized value `v` satisfies `v ≡ original` under the type's semantic equivalence relation (field-by-field equality for types that derive PartialEq).
- **Invariant 1:** Round-trip produces a semantically equivalent value — not necessarily identical memory representation.
- **Invariant 4:** Round-trip is deterministic — no random state injected.
- **Precondition 3:** The type is registered in the inventory via `inventory::submit! { LcEntry { ... } }` and the Reviver's registry contains a matching entry.

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|----------|
| Property-based testing | proptest (fast-check analog) | N/A — proptest generates random inputs | For each registered core type: arbitrary instances generated via `proptest::arbitrary::Arbitrary`; assert `revive(serialize(x)) ≡ x` over hundreds of random inputs; covers field boundary values, optional fields set to None/Some, empty strings, unicode content |

**Proptest strategy:** For each `T: LcSerializable + Arbitrary`, the strategy generates:
- Arbitrary field values within the type's domain (using `proptest::arbitrary::any::<T>()`)
- Edge-case seeds: empty strings, whitespace-only strings, unicode, max-length strings

The proptest suite covers all 141 registered core types. Each type gets its own proptest case
function tagged with `#[proptest]`. Types without `Arbitrary` derivation get hand-written
strategies. The suite runs during `cargo nextest run -p ferrochain-core` in Phase 3.

**Why proptest and not Kani:** `LcSerializable::serialize` and `Reviver::revive` are
pure-core synchronous functions. However, the round-trip property requires generating
arbitrary instances of all 141 registered types — a combinatorially large input space that
exceeds practical Kani model-checking bounds. Proptest's shrinking mechanism also
produces compact counterexamples when a round-trip fails, making it more actionable than
Kani's bounded exhaustion for this property. Kani is reserved for safety-critical reachability
proofs (VP-010 covers the rejection path). The round-trip liveness property is well-served
by proptest's randomized coverage.

## Proof Harness Skeleton

Target file: `ferrochain-core/src/serializable.rs` (proptest cases in `#[cfg(test)] mod tests`)

```rust
// ferrochain-core/src/serializable.rs — within #[cfg(test)] mod tests

#[cfg(test)]
mod tests {
    use super::*;
    use proptest::prelude::*;

    /// VP-007: LcSerializable Round-Trip
    /// Strategy: arbitrary PromptTemplate → serialize → revive → assert equivalence.
    proptest! {
        #[test]
        fn prop_prompt_template_round_trip(
            template_str in "[a-zA-Z ]{1,128}\\{name\\}",
        ) {
            let pt = PromptTemplate {
                template: template_str,
                input_variables: vec!["name".to_string()],
            };

            let serialized = pt.serialize();
            prop_assume!(matches!(serialized, Serialized::Constructor { .. }));

            let reviver = Reviver::new(); // uses OnceLock — populated at program start
            let revived = reviver.revive(serialized).expect("registered type must round-trip");

            let revived_pt = revived.downcast::<PromptTemplate>()
                .expect("downcast to PromptTemplate must succeed");
            prop_assert_eq!(*revived_pt, pt, "round-trip must produce semantically equivalent value");
        }

        #[test]
        fn prop_system_message_round_trip(
            content in ".*{0,512}",
        ) {
            let msg = SystemMessage { content };
            let serialized = msg.serialize();

            let reviver = Reviver::new();
            let revived = reviver.revive(serialized).expect("SystemMessage must round-trip");
            let revived_msg = revived.downcast::<SystemMessage>()
                .expect("downcast must succeed");

            prop_assert_eq!(*revived_msg, msg, "SystemMessage round-trip must be equivalent");
        }
    }

    /// VP-007: determinism — calling serialize→revive twice produces the same result
    #[test]
    fn round_trip_is_deterministic() {
        let pt = PromptTemplate {
            template: "hello {name}".to_string(),
            input_variables: vec!["name".to_string()],
        };

        let reviver = Reviver::new();

        let result1 = reviver.revive(pt.serialize()).unwrap();
        let result2 = reviver.revive(pt.serialize()).unwrap();

        let pt1 = result1.downcast::<PromptTemplate>().unwrap();
        let pt2 = result2.downcast::<PromptTemplate>().unwrap();

        assert_eq!(*pt1, *pt2, "serialize→revive must be deterministic");
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded per type | proptest generates hundreds of inputs per property; shrinking finds minimal counterexamples quickly |
| Proof complexity | Medium | 141 types require strategies; types without `Arbitrary` need hand-written strategies (~15 estimated) |
| Tool support | Supported | proptest 1.x; standard `#[cfg(test)]` integration; runs in `cargo nextest` |
| Estimated proof time | < 30s per type; < 10 min total | 141 × ~2s proptest budget = ~5 min; CI budget covers this in Phase 3 |

Key factors:
1. `LcSerializable::serialize` and `Reviver::revive` are pure-core sync functions (ADR-016
   Decision 1; no I/O, no async). Proptest exercises them as pure functions.
2. The round-trip property is well-defined: `PartialEq` on registered types provides the
   semantic equivalence relation. Types without `PartialEq` need documented equivalence criteria.
3. Secret fields (`lc_secrets()`) are stripped in serialize and not available in kwargs during
   revive — BC-2.19.002 specifies this behavior and it is OUT OF SCOPE for the round-trip VP
   (secret fields are not part of the round-trip equivalence; VP-007 covers non-secret fields only).

**Known constraint:** Types with credential fields (`lc_secrets()` non-empty) cannot fully
round-trip through kwargs — credentials are stripped during serialize and reconstructed via
DI during revive (BC-2.19.002). The round-trip equivalence for these types applies to
non-credential fields only. The proptest strategy must use instances with credential fields
set to `None` or to sentinel values that survive the round-trip.
