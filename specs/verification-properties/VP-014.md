# VP-014: RunnableParallel Key-Completeness — Output Key Set Equals Configured Branch Key Set on Success

## Property Statement

For any `N`-branch `RunnableParallel` invocation where `invoke` returns `Ok(output)`:
1. `output.as_object().unwrap().len() == N` (exactly `N` keys in the output object)
2. The output key set is exactly equal to the configured branch key set (i.e., the set of keys passed to `RunnableParallel::new(steps)`)

This property holds for all `N ≥ 0`, for all arbitrary collections of distinct branch keys,
and for any branch runnables that return `Ok`.

**Formal invariant (DI-016 key-completeness half):**
```
// new() accepts an iterator of (key, runnable) pairs — the canonical argument type
// per BC-2.01.005 PC1. IndexMap is the INTERNAL container built by new(), not the
// argument type (ADR-026 §Decision 1).
∀ steps: Vec<(String, Arc<dyn DynRunnable>)>, ∀ input: Value:
  let key_set: HashSet<String> = steps.iter().map(|(k, _)| k.clone()).collect();
  let N = key_set.len();
  let result = RunnableParallel::new(steps).invoke(input, None).await;
  if let Ok(output) = result {
    let obj = output.as_object().unwrap();
    obj.len() == N
    ∧ obj.keys().cloned().collect::<HashSet<_>>() == key_set
  }
```

The complementary invariant (DI-016 branch-failure-propagation half) — that a failing branch
produces `Err` and not a partial object — is contractually specified in BC-2.01.006 and is
covered by unit tests on the failure path. VP-014 verifies the success-path completeness half.

## Source Contract

- **Primary BC:** BC-2.01.005 — RunnableParallel Construction and Concurrent Invocation (VP-014 proptest obligation)
- **Secondary BC:** BC-2.01.006 — RunnableParallel Branch Failure (success-path invariant: VP-014 proves the Ok path always has N keys, which together with BC-2.01.006's "no partial result on failure" establishes the all-or-nothing guarantee)
- **ADR anchor:** ADR-026 §Decision 1 (type representation and key ordering) and ADR-026 §Decision 2 (JoinSet fan-out, completion-order collection, re-insertion in steps order)
- **Postcondition 3 (BC-2.01.005):** "On success (all N branches return Ok): returns Ok(serde_json::Value::Object(map)) where map has exactly N keys, each key equal to its branch's configured name"
- **Postcondition 4 (BC-2.01.005):** "The output object key order equals the steps IndexMap insertion order — verified by re-inserting results keyed by self.steps.keys() after collection"
- **Invariant — All-or-nothing success (BC-2.01.005):** "Either all N branches contribute a key to the output object, or the invocation returns Err"
- **Invariant — No partial result on failure (BC-2.01.006):** "Returning Ok(Value::Object(...)) with fewer than N keys is a contract violation"
- **TV-003 (BC-2.01.005):** 3-branch parallel where output order should equal insertion order ["a", "b", "c"] regardless of which branch finishes first

## Proof Method

| Method | Tool | Bounded? | Coverage |
|--------|------|----------|---------|
| Property-based testing | proptest | Yes — generates arbitrary N (0..=20), arbitrary distinct branch keys (UTF-8 strings), and identity-branch runnables (return Ok(input.clone())) | All N in [0,20], random key sets; statistical confidence for larger N |

**Why proptest rather than Kani:**
`RunnableParallel::invoke` is an `async fn` that spawns Tokio tasks via `JoinSet`.
Kani 0.67.0 has no native async support and cannot model Tokio runtime semantics. proptest
is the correct tool for this property: it generates random inputs (branch counts, key names),
exercises the actual async runtime, and verifies the key-set property on each generated case.
The property is parameterized over a large but finite input domain; proptest gives statistical
confidence that no combination of N and key set violates the property.

**Harness boundary:**
- Branch runnables: identity functions (`|input| Ok(input.clone())`) — pure, infallible, zero I/O
- Input: `Value::String("test_input")` — valid input that all branches accept
- Branch count: proptest-generated in range `0..=20` (covers zero, one, small N, medium N)
- Key names: proptest-generated distinct alphanumeric strings of length 1..=20
- Runtime: single-threaded Tokio runtime (`#[tokio::test]` or `Runtime::new()`) per test case

The proptest harness runs in Phase 3 (TDD), exercising the production `RunnableParallel` implementation.

## Proof Harness Skeleton

Target file: `pregolya-core/src/runnable/parallel.rs` (or `pregolya-core/tests/proptest_parallel.rs`)

```rust
// pregolya-core/tests/proptest_parallel.rs
// VP-014: RunnableParallel key-completeness property

use futures::{Stream, stream};
use pregolya_core::runnable::{DynRunnable, RunnableConfig, RunnableParallel};
use proptest::prelude::*;
use serde_json::Value;
use std::pin::Pin;
use std::sync::Arc;
use tokio::runtime::Runtime;

/// A trivial identity runnable for proptest: always returns Ok(input).
struct IdentityRunnable;

impl DynRunnable for IdentityRunnable {
    async fn invoke(
        &self,
        input: Value,
        _config: Option<RunnableConfig>,
    ) -> Result<Value, pregolya_core::PregolyaError> {
        Ok(input)
    }

    /// Single-item stream returning the input unchanged.
    /// Required trait item — DynRunnable::stream has no default body (E0046 without this).
    /// Not exercised by the key-completeness property but must compile.
    async fn stream(
        &self,
        input: Value,
        _config: Option<RunnableConfig>,
    ) -> Pin<Box<dyn Stream<Item = Result<Value, pregolya_core::PregolyaError>> + Send>> {
        Box::pin(stream::once(async move { Ok(input) }))
    }
}

proptest! {
    /// VP-014: For any N-branch RunnableParallel with all-Ok branches:
    /// invoke returns Ok(output) where output.as_object().len() == N
    /// and the key set equals the configured branch key set.
    #[test]
    fn parallel_key_completeness(
        // Generate N distinct keys of length 1..=10 as branch names
        keys in proptest::collection::hash_set(
            "[a-z][a-z0-9]{0,9}",  // distinct alphanumeric keys
            0usize..=20,
        )
    ) {
        // Synchronous setup hoisted to function body level (VP-016 §Proof Harness Skeleton body-level idiom).
        // prop_assert!/prop_assert_eq! expand to early-return Err(TestCaseError) and MUST NOT
        // be placed inside rt.block_on(async{}) — they cannot cross the async boundary
        // (E0308) and would be silently swallowed if coerced (false-green).
        let n = keys.len();
        let steps: Vec<(String, Arc<dyn DynRunnable>)> = keys
            .iter()
            .cloned()
            .map(|k| (k, Arc::new(IdentityRunnable) as Arc<dyn DynRunnable>))
            .collect();
        let key_set: std::collections::HashSet<String> = keys;
        let parallel = RunnableParallel::new(steps);
        let input = Value::String("test_input".to_string());

        // Only the single async call inside block_on; result bound at body level.
        let rt = Runtime::new().unwrap();
        let result = rt.block_on(async { parallel.invoke(input, None).await });

        // All VP-014 assertions at function body level (outside block_on).
        match result {
            Ok(output) => {
                let obj = output.as_object().expect("output must be a JSON object");
                prop_assert_eq!(
                    obj.len(), n,
                    "output must have exactly N={} keys", n
                );
                let output_keys: std::collections::HashSet<String> =
                    obj.keys().cloned().collect();
                prop_assert_eq!(
                    output_keys, key_set,
                    "output key set must equal configured branch key set"
                );
            }
            Err(e) => {
                prop_assert!(false, "expected Ok but got Err: {:?}", e);
            }
        }
    }
}
```

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded by proptest config | N ∈ [0, 20]; distinct key strings; proptest generates 256 cases by default |
| Proof complexity | Low | Identity-branch runnables are zero-cost; JoinSet fan-out is the only async machinery being exercised |
| Tool support | Supported (Phase 3) | proptest 1.x + Tokio; identity runnables avoid any LLM API calls; pure-core async only |
| Estimated test time | < 2s per case; < 1 min total | 256 proptest cases × identity runnables; dominated by Tokio task spawn overhead |

Key factors:
1. The property is over pure-core async behavior with zero I/O — all branches are identity functions.
   No LLM API keys, no network, no filesystem access required.
2. The key-completeness property is a structural invariant of `RunnableParallel::invoke`
   — it holds whenever the re-insertion-in-steps-order logic is correct and all N tasks complete with Ok.
3. proptest with N up to 20 gives high statistical confidence; the invariant is deterministic
   for identity runnables (no timing or ordering variance in the output key set).

## Proof Obligations

- [ ] `RunnableParallel::new(steps)` accepts `Vec<(String, Arc<dyn DynRunnable>)>` and produces a well-formed parallel combinator
- [ ] `invoke` with N all-Ok identity branches returns `Ok(Value::Object)` with exactly N keys
- [ ] Output key set equals the step key set passed to `new()`
- [ ] Zero-branch case: `invoke` returns `Ok(Value::Object({}))` — empty object, len=0
- [ ] Harness compiles under `cargo nextest run -p pregolya-core` with proptest feature enabled
- [ ] All 256 proptest cases pass within the 1-minute CI time budget

## BC Contradictions Flagged

No contradictions. BC-2.01.005 §Postcondition 3 (exactly N keys) and §Postcondition 4 (key order = insertion order)
are consistent with this VP's property. Note: this VP proves the **set equality** property
(keys match as a set); the **ordering** property (insertion-order preserved) is a separate
behavioral test that proptest partially covers but is not the primary focus of VP-014 (proptest
doesn't guarantee specific ordering in generated test cases; insertion-order is verified by
the dedicated test vector TV-003 in BC-2.01.005).
