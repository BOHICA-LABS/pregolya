# VP-006: injection_guard Fail-Closed — TrustRequired Slot with Untrusted TrustLevel Never Produces PromptValue

## Property Statement

For any `ChatPromptTemplate` and any variable map passed to `format_messages`, if at least
one `TrustRequired` slot receives a variable whose `TrustLevel::is_untrusted()` returns
`true`, `format_messages` returns `Err(E-TMPL-001)` and no `PromptValue` is produced.

**Formal invariant (DI-014):** `∀ template: ChatPromptTemplate, vars: HashMap<String, TemplateInput>,
  (∃ slot ∈ template.slots: slot.policy == TrustRequired ∧
   ∃ input ∈ vars_for_slot(slot):
     (input == Scalar(v) ∧ v.trust_level.is_some_and(|t| t.is_untrusted())) ∨
     (input == Messages(m) ∧ m.trust_level.is_some_and(|t| t.is_untrusted())) ∨
     (input == FewShotExamples(pairs) ∧ ∃ (iv, ov) ∈ pairs:
       iv.trust_level.is_some_and(|t| t.is_untrusted()) ∨
       ov.trust_level.is_some_and(|t| t.is_untrusted())))
  → format_messages(vars) == Err(PregolyaError { code: "E-TMPL-001", category: SECURITY, .. })`

Note: `TemplateInput` is the unified parameter type per ADR-015 §Decision 3 Amendment —
TemplateInput Enum Concretized. Prior form used `HashMap<String, TemplateVar>` (Scalar only).

No reachable code path through `injection_guard` may produce `Ok(PromptValue)` when the
above precondition holds. The check is unconditional — no feature flag, no debug mode, no
bypass path.

## Source Contract

- **BC:** BC-2.18.004 — injection_guard — SystemMessage Slot with TrustLevel::Untrusted Raises E-TMPL-001 (Fail-Closed at Render Time)
- **Postcondition 1:** `format_messages` returns `Err(PregolyaError { code: "E-TMPL-001", category: SECURITY, .. })` — no partial `PromptValue` produced.
- **Postcondition 2:** No `PromptValue` is produced — rendering aborts at the first failing slot.
- **Invariant 1:** The injection_guard check fires unconditionally for every TrustRequired slot on every call — no bypass path exists.
- **Invariant 3:** The check is a **pure-core synchronous function** — no I/O, no async, no external dependencies. This grounds the Kani VP-006 candidacy.
- **Invariant 4:** `PromptValue` carrying `MessageProvenance.highest_trust_level == Some(TrustLevel::Untrusted)` with `slot_trust_policy == TrustRequired` is a type-level invariant — no such instance can be constructed.

**Kani async constraint (Kani 0.67.0 has NO native async support):** `injection_guard` and
`format_messages` are pure-core synchronous functions (ADR-015 Decision 3 explicitly states:
"pure-core synchronous function — no I/O, no async, no external dependencies"). The Kani
harness calls the sync injection-guard logic directly without any `.await` or Tokio runtime.
No `block_on` adaptation is needed — the proof target is natively sync.

**Harness boundary:** The proof covers `injection_guard::check_slot_trust(slots, vars) → Result<(), PregolyaError>` (the extracted pure-core check), not the full `format_messages` pipeline. The implementer extracts this function to be the Kani target; the async wrapper (`format_messages` callers via the graph) is excluded from the proof scope.

## Proof Harness Skeleton

Target file: `pregolya-prompts/src/injection_guard.rs`

```rust
// pregolya-prompts/src/proofs/injection_guard.rs
//
// VP-006 harness — covers TemplateInput::Scalar and TemplateInput::Messages arms.
// TemplateInput::FewShotExamples arm: see §FewShot harness note below.

#[cfg(kani)]
mod proofs {
    use super::*;

    /// Helper: extract trust level from a TemplateInput arm for injection check.
    /// Returns the "worst" (highest-severity) trust level present in the input.
    fn input_trust_level(input: &TemplateInput) -> Option<TrustLevel> {
        match input {
            TemplateInput::Scalar(v) => v.trust_level,
            TemplateInput::Messages(m) => m.trust_level,
            // FewShotExamples: return untrusted if either component is untrusted.
            // (Covered separately in injection_guard_fewshot_fail_closed below.)
            TemplateInput::FewShotExamples(pairs) => pairs.iter().find_map(|(iv, ov)| {
                if iv.trust_level.is_some_and(|t| t.is_untrusted())
                    || ov.trust_level.is_some_and(|t| t.is_untrusted())
                {
                    Some(TrustLevel::Untrusted)
                } else {
                    None
                }
            }),
        }
    }

    /// VP-006 — Main harness: Scalar and Messages arms.
    /// Proves: no path from (TrustRequired + is_untrusted()) reaches Ok.
    #[kani::proof]
    fn injection_guard_fail_closed() {
        // Bound: up to 4 slots per template (keep state space finite)
        let n_slots: usize = kani::any();
        kani::assume(n_slots >= 1);
        kani::assume(n_slots <= 4);

        // Symbolic slots: each has a policy and a TemplateInput (Scalar or Messages arm only)
        let slot_vars: Vec<SlotVar> = (0..n_slots)
            .map(|_| {
                let policy: SlotTrustPolicy = kani::any();
                // Choose between Scalar and Messages (0 = Scalar, 1 = Messages)
                let arm: u8 = kani::any();
                kani::assume(arm <= 1);
                let trust_level: Option<TrustLevel> = kani::any();
                let input = if arm == 0 {
                    TemplateInput::Scalar(TemplateVar {
                        value: String::new(), // content irrelevant to trust check
                        trust_level,
                    })
                } else {
                    TemplateInput::Messages(MessageListVar {
                        messages: vec![], // list content irrelevant to trust check
                        trust_level,
                    })
                };
                SlotVar { policy, input }
            })
            .collect();

        // Precondition: at least one TrustRequired slot with an Untrusted input
        let injection_present = slot_vars.iter().any(|sv| {
            sv.policy == SlotTrustPolicy::TrustRequired
                && input_trust_level(&sv.input).is_some_and(|t| t.is_untrusted())
        });

        if injection_present {
            let result = check_slot_trust(&slot_vars);
            kani::assert(
                matches!(result, Err(PregolyaError { code: "E-TMPL-001", .. })),
                "injection_guard must return E-TMPL-001 when TrustRequired slot has Untrusted input"
            );
        }
    }

    /// VP-006 — FewShotExamples arm: untrusted example component in TrustRequired slot → Err.
    #[kani::proof]
    fn injection_guard_fewshot_fail_closed() {
        let policy = SlotTrustPolicy::TrustRequired;
        // Symbolic trust levels for example input and output components
        let input_trust: Option<TrustLevel> = kani::any();
        let output_trust: Option<TrustLevel> = kani::any();
        // Precondition: at least one component is untrusted
        kani::assume(
            input_trust.is_some_and(|t| t.is_untrusted())
                || output_trust.is_some_and(|t| t.is_untrusted())
        );
        let input = TemplateInput::FewShotExamples(vec![(
            TemplateVar { value: String::new(), trust_level: input_trust },
            TemplateVar { value: String::new(), trust_level: output_trust },
        )]);
        let sv = SlotVar { policy, input };
        let result = check_slot_trust(&[sv]);
        kani::assert(
            matches!(result, Err(PregolyaError { code: "E-TMPL-001", .. })),
            "injection_guard must return E-TMPL-001 for untrusted FewShot component in TrustRequired slot"
        );
    }

    /// Negative: TrustAll slot with Untrusted Scalar → no error
    #[kani::proof]
    fn trust_all_slot_allows_untrusted() {
        let input = TemplateInput::Scalar(TemplateVar {
            value: String::new(),
            trust_level: Some(TrustLevel::Untrusted),
        });
        let sv = SlotVar { policy: SlotTrustPolicy::TrustAll, input };
        let result = check_slot_trust(&[sv]);
        kani::assert(result.is_ok(), "TrustAll slot must accept Untrusted variable");
    }

    /// Negative: TrustRequired slot with Trusted Scalar → no error
    #[kani::proof]
    fn trust_required_trusted_var_passes() {
        let input = TemplateInput::Scalar(TemplateVar {
            value: String::new(),
            trust_level: Some(TrustLevel::Trusted),
        });
        let sv = SlotVar { policy: SlotTrustPolicy::TrustRequired, input };
        let result = check_slot_trust(&[sv]);
        kani::assert(result.is_ok(), "TrustRequired slot must accept Trusted variable");
    }
}
```

**§FewShot harness note:** The `injection_guard_fewshot_fail_closed` harness covers
`TemplateInput::FewShotExamples` with a single-pair example list. The Vec-length bound
of the main harness (≤ 4 slots) applies to the slot count; the example list itself is
bounded to 1 pair in this harness for tractability. A separate property test (not Kani)
should cover multi-pair example lists where only a middle pair is untrusted.

## Feasibility Assessment

**Feasibility: HIGH**

| Factor | Assessment | Notes |
|--------|-----------|-------|
| Input space size | Bounded | TrustLevel has 3 variants; SlotTrustPolicy has 2 variants; template bounded to ≤ 4 slots — full enum coverage is tractable |
| Proof complexity | Low | Single conditional: `policy == TrustRequired && trust_level.is_some_and(\|t\| t.is_untrusted())` → Err; no unbounded loops; no recursion |
| Tool support | Supported | Kani 0.67.0; proof target is pure-core sync; `TrustLevel` (3-variant fieldless enum) and `SlotTrustPolicy` (2-variant enum) — `kani::Arbitrary` derivable without bounds |
| Estimated proof time | < 2 min | 2-variant × 3-variant enum; 1..4 slot bound; minimal state space |

Key factors:
1. `injection_guard` is explicitly classified as "pure-core synchronous function — no I/O, no async" (ADR-015 Decision 3). No adaptation needed for Kani 0.67.0.
2. Both enum types (`TrustLevel` and `SlotTrustPolicy`) are finite and bounded without additional `kani::assume`. Kani exhaustively explores all enum variant combinations.
3. The proof obligation reduces to: one conditional over a bounded Vec — a trivially tractable property.

**No blocking risks.** The only implementer obligation is extracting `check_slot_trust` as a standalone pure function (not an inline block inside `format_messages`) so that the Kani harness can import and call it directly. This is a standard pure-core extraction pattern.
